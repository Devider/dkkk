# Подбор входа под цель

Применяй, когда пользователь называет целевое значение показателя (выхода) в конкретном году и спрашивает, каким должен быть вход.

Не этот skill:
- «Посчитай Y при X от a до b», «при падении X на 10–30 %» — сценарная сетка (`scenario-analysis`);
- «при какой цене DSCR опустится до 1,2» по диапазону цен — сетка и точка пересечения порога (`scenario-analysis`).

## Шаблон плана

Образец шагов — формулируй их под запрос, не копируй текст дословно.

1. Сопоставить показатели запроса с моделью.
2. Базовые значения <вход> и <выход> в <год>.
3. Подбор <вход>, при котором <выход> в <год> = <цель>.
4. Отклонение найденного значения от базы.
5. Вывод.

## Шаг 1. Сопоставление

- Один вызов `resolve_terms`: показатель с целью — `role: output`, подбираемые входы — `role: input`.
- Уверенность `high` — бери первого кандидата и не спрашивай пользователя о выборе показателя.
- Уверенность `low` — сверь кандидатов с запросом по смыслу. Спрашивай, только если по смыслу подходят двое и более, и называй их названиями модели, без ID.

## Шаг 2. Базовые значения

Один вызов `get_values` с ID входа и выхода за год цели. Это база для отклонения (шаг 4) и для вывода «насколько далеко цель от текущего плана».

## Шаг 3. Подбор — правила аргументов

`find_input_for_target` всегда вызывай со всеми четырьмя аргументами:
- `output_id` — ID выхода из шага 1;
- `year` — год цели **из запроса**;
- `target` — целевое значение **из запроса**, числом без единиц, в единицах выхода (для показателя с единицей «доля»: 12 % = 0,12);
- `input_ids` — ID подбираемых входов из шага 1.

`tolerance` не передавай, если пользователь не назвал допуск.

**Нет года или цели** — не считай: поставь шаг подбора в `blocked` с причиной («не указан год», «не указано целевое значение») и закончи ход одним вопросом ровно о недостающем. Не бери «текущий год», последний год модели или базовое значение выхода как цель.

«Не меньше 1000», «хотя бы 1,2», «не выше 3» — это цель 1000, 1,2, 3: подбирай равенство и скажи в «Оговорках», что найдено значение входа для равенства — границы условия.

## Шаг 4. Отклонение от базы

Не считай в уме — вызывай `derive`:
- `pct_change`: `a` — базовое значение входа (шаг 2), `b` — найденное значение входа (шаг 3);
- `difference` — с теми же `a` и `b`, когда нужен абсолютный сдвиг.

Числа передавай так, как они указаны в результатах.

## Цель недостижима

Если результат подбора говорит, что цель не достигнута (`reachable: false`), — это не ошибка, а ответ:
- в «Выводе»: «Недостижимо: максимум <выход> — <значение> при <вход> = <значение>» по ближайшему сценарию из результата;
- не повторяй подбор с другими входами или целью, если пользователь об этом не просил; можно предложить это одной фразой.

## Ошибки и что делать

| Код | Что делать |
| --- | --- |
| `missing_input` | Не повторяй вызов без аргументов. Возьми год, цель и входы из запроса и шага 1; чего нет в запросе — шаг `blocked` и вопрос. |
| `invalid_args` про год | Скажи, за какие годы есть значения, и спроси год. |
| `no_values` | Это заголовок раздела, а не показатель — вернись к сопоставлению и выбери другого кандидата. |
| `unknown_id` | Бери ID только из результата `resolve_terms`. |

## Ответ

Разделы — по правилам оформления ответа (`economic-answer`). Для подбора:

- **Вывод** — найденное значение входа и что это значит: насколько оно выше / ниже текущего (по шагу 4).
- **Ключевые цифры** — строки: база входа, найденное значение входа, значение выхода при найденном входе (из результата подбора), база выхода, отклонение от базы (из `derive`).
- **Оговорки** — если цель достигнута не точно, а в пределах допуска: «значение выхода <значение> вместо <цель>».
