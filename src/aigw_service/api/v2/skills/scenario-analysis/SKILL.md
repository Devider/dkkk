# Сценарный анализ: показатели по сетке значений входа

Применяй, когда пользователь просит пересчитать показатели при других значениях входа: диапазоном («от 300 до 500»), относительным изменением («на 10–30 %», «±20 %») или одной точкой («а если цена 500»).

Не этот skill: «какой должна быть X, чтобы Y = Z» — подбор под цель (`target-seeking`).

## Шаблон плана

Образец шагов — формулируй их под запрос, не копируй текст дословно. Шаги 2 и 4 добавляй по правилам ниже.

1. Сопоставить показатели запроса с моделью.
2. Базовое значение <вход> в <год> — **обязательно** для относительного диапазона и для одной точки; для абсолютного — когда спрашивают «как изменится».
3. Сетка: <выходы> в <год> при <вход> от <начало> до <конец>, шаг <шаг>.
4. Изменения к базе — когда спрашивают «как изменится», «на сколько упадёт».
5. Вывод.

Если в запросе есть часть «при какой цене Y = порог» — добавь шаг «точка пересечения порога» по результатам сетки (`derive`, операция `crossing`).

## Шаг 1. Сопоставление

- Один вызов `resolve_terms` по всем терминам: входы — `role: input`, выходы — `role: output`.
- Уверенность `high` — бери первого кандидата и не спрашивай пользователя о выборе показателя.
- Уверенность `low` — сверь кандидатов с запросом по смыслу. Спрашивай, только если по смыслу подходят двое и более, и называй их названиями модели, без ID.

## Шаг 2. Базовое значение

- `get_values` по ID входа за год расчёта. Если за этот год значения нет, `get_values` скажет об этом в заметках — возьми значение ближайшего года и напиши об этом в «Оговорках».
- Для «как изменится» — в тот же вызов добавь ID выходов: их значения за год и есть база для сравнения.

## Шаг 3. Сетка — правила аргументов

`run_scenarios`: `inputs` — ID входа и `min`, `max`, `step`; `outputs` — ID выходов; `year` — год.

**Год.** Только из запроса. Нет года — не считай: поставь шаг сетки в `blocked` с причиной «не указан год» и закончи ход одним вопросом о годе. Не бери «текущий год» и не бери последний год модели. Несколько лет — отдельный вызов `run_scenarios` на каждый год.

**Абсолютный диапазон** («от 300 до 500») — `min` и `max` как в запросе.

**Относительный диапазон** — от базового значения из шага 2:
- «±20 %»: `min` = база × 0,8, `max` = база × 1,2;
- «падение на 10–30 %»: `min` = база × 0,7, `max` = база × 0,9;
- «рост на 5–15 %»: `min` = база × 1,05, `max` = база × 1,15.

Эти числа — аргументы инструмента. В ответе границы сетки бери из результата `run_scenarios` (там есть каждое значение сетки), а не из своей арифметики.

**Шаг сетки.** Если пользователь назвал шаг — бери его (шаг в процентах — от базы: «шаг 10 %» = база × 0,1). Если не назвал — **не спрашивай**: сетка из 5 точек, `step` = (`max` − `min`) / 4. Примеры: «от 300 до 500» → шаг 50; «±20 %» → шаг 10 % от базы; «падение на 10–30 %» → шаг 5 % от базы. В «Оговорках» обязательно скажи, что шаг выбран по умолчанию, и перечисли точки сетки из результата `run_scenarios`. Само число шага не пиши: его нет в результатах, а в ответе — только числа из результатов.

**Одна точка** («а если цена 500»): `min` = `max` = 500, `step` = 1. Сравни с базой из шага 2.

**Диапазон не назван вовсе** («посчитай EBITDA при другой цене») — не придумывай: шаг сетки `blocked`, один вопрос о диапазоне.

**Единицы.** Диапазон — в тех же единицах, что базовое значение. Если `get_values` показывает единицу «доля», то 5 % = 0,05.

**Несколько входов** перемножают точки сетки. Держи сетку небольшой: по 3 точки на вход, если шаг не назван.

## Шаг 4. Изменения к базе

Разницу и процент изменения не считай в уме — вызывай `derive`:
- `pct_change`: `a` — база выхода (шаг 2), `b` — значение выхода в крайней точке сетки;
- `difference` — то же, когда нужен абсолютный прирост;
- `crossing` — точки ряда из сетки (`x` — значение входа, `y` — выхода) и порог из запроса;
- `elasticity` — две точки сетки, когда спрашивают о чувствительности.

Числа в `derive` передавай так, как они указаны в результатах.

## Ошибки и что делать

| Код | Что делать |
| --- | --- |
| `missing_input` | Не повторяй вызов с теми же аргументами. Возьми недостающее из запроса; если там его нет — шаг `blocked` и вопрос. Не названный шаг сетки — не вопрос: правило «5 точек». |
| `bad_units` | Пересчитай диапазон в единицы базы (доля / %) и повтори один раз. |
| `invalid_args` про год | Скажи, за какие годы есть значения, и спроси год. |
| `invalid_args` про лимит сетки | Увеличь шаг или сократи число входов, повтори; в «Оговорках» скажи, что сетка сокращена до лимита. |
| `invalid_args` про диапазон | Начало должно быть не больше конца, шаг — больше нуля. Исправь и повтори. |
| `no_values` | Это заголовок раздела, а не показатель — вернись к сопоставлению и выбери другого кандидата. |

## Ответ

Разделы — по правилам оформления ответа (`economic-answer`). Для сценарного запроса:

- **Ключевые цифры** — строка на точку сетки: в первом столбце условие («Метанол = 320»), дальше год, значение, единицы. База — отдельной строкой («База: Метанол = 400»), если считали шаг 2.
- **Анализ** — направление и крутизна изменения по сетке, изменения к базе и точка пересечения порога — только из `derive`.
- **Оговорки** — обязательно, если было хотя бы одно из:
  - относительный диапазон: «±<a> % от базы <база> → <начало>–<конец>»;
  - шаг сетки не назван пользователем: «шаг не назван — сетка из 5 точек: <точки из результата>»;
  - база взята за ближайший год.

Пример оговорки (числа условные): «Диапазон ±20 % от базы 400 → 320–480; шаг не назван — сетка из 5 точек: 320, 360, 400, 440, 480».
