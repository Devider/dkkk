# Драйверы показателя: рейтинг влияния и объяснение изменения

Применяй, когда спрашивают, от чего зависит показатель, что на него сильнее влияет, или почему он изменился между годами.

Не этот skill: «посчитай Y при X от a до b» — сценарная сетка (`scenario-analysis`); запас до порога ковенанта — `covenant-headroom`.

Этот skill открывает инструмент `trace_dependencies`: он по формулам книги показывает, от каких входов модели зависит выход за год, и через какие промежуточные выходы идёт связь. Пересчёт он не запускает.

Выбери ветку:
- **А — рейтинг влияния**: «что сильнее влияет на Y», «ключевые драйверы Y», «чувствительность Y».
- **Б — почему изменился**: «почему просел Y», «почему Y в 2027 ниже, чем в 2026».

## Ветка А. Шаблон плана

Образец шагов — формулируй их под запрос, не копируй текст дословно.

1. Драйверы: сопоставить <показатель>; найти входы, от которых он зависит.
2. Сдвиг ±<N> % по каждому драйверу: сетка <показатель> в <год>.
3. Эластичности по каждому драйверу.
4. Рейтинг драйверов по силе влияния.
5. Связи в модели.
6. Вывод.

### Шаг 1. Драйверы

- `resolve_terms` для показателя (`role: output`) и для драйверов, если пользователь их назвал (`role: input`).
- Драйверы не названы — `trace_dependencies` по ID показателя и году. Возьми до 5 входов с наименьшей глубиной. Затем `get_values` по этим входам за год: вход с базой 0 или без значения пропусти — для него нет эластичности.
- Драйверы названы — бери их (не больше 5); `trace_dependencies` вызови на шаге 5 для связей.
- Если в результате `trace_dependencies` есть оговорка, что название входа повторяется и связь идёт через другую строку, — такой вход тоже считай, а оговорку перенеси в ответ.

**Год** — только из запроса. Нет года — шаг сетки в `blocked` с причиной «не указан год» и один вопрос о годе. Не бери «текущий» или последний год модели.

### Шаг 2. Сдвиг по каждому драйверу

**Отдельный вызов `run_scenarios` на каждый драйвер** — один вход в `inputs`. Несколько входов в одной сетке перемножаются и не дают влияния каждого.

Сетка из двух точек вокруг базы из `get_values`:
- `min` = база × 0,9, `max` = база × 1,1, `step` = `max` − `min` — сдвиг ±10 %. Если округляешь числа, округляй шаг вниз: шаг больше `max` − `min` даст сетку из одной точки.

**Сдвиг ±N %.** Если пользователь назвал сдвиг («при изменении на ±20 %»), бери его: «±20 %» — `min` = база × 0,8, `max` = база × 1,2, `step` = `max` − `min`. Если не назвал — **не спрашивай**: ±10 % от базы, и в «Оговорках» напиши, что сдвиг ±10 % выбран по умолчанию.

Единицы — как у базы: если база в долях («доля»), сдвиг считается от доли (база 0,05 → 0,045 и 0,055).

**Сдвиг в ответе.** Число сдвига в ответе должно быть из результата, а не из этого правила: один раз вызови `derive`, операция `pct_change`, `a` — база первого драйвера, `b` — верхняя точка его сетки из результата `run_scenarios`. Результат (например, «10 %») и пиши в «Оговорках».

### Шаг 3. Эластичности

На каждый драйвер — `derive`, операция `elasticity`: `points` — две точки из результата его сетки (`x` — значение драйвера, `y` — значение показателя), числа так, как они указаны в результате. Эластичность — на сколько процентов меняется показатель при изменении драйвера на 1 %.

Не считай эластичность и проценты в уме — только `derive`.

### Шаг 4. Рейтинг

Упорядочи драйверы по модулю эластичности — от сильного к слабому. Рейтинг — это порядок строк, новых чисел не придумывай. Знак эластичности: «+» — показатель растёт вместе с драйвером, «−» — падает.

### Шаг 5. Связи в модели

Из результата `trace_dependencies` — через какие промежуточные выходы драйверы влияют на показатель («Метанол → Выручка → EBITDA → DSCR»). Пиши названиями показателей.

### Лимит расчётов

Каждый драйвер — один расчёт; 5 драйверов — 5 расчётов. Если пришёл `limit_exceeded`, больше не считай: дай рейтинг по уже посчитанным драйверам, а остальные перечисли в «Оговорках».

## Ветка Б. Почему показатель изменился

Если в этом диалоге уже есть выжимка прошлого хода с нужными цифрами, отвечай по ней без инструментов.

Иначе шаблон плана:

1. Сопоставить <показатель>.
2. Значения <показатель> за <год сравнения> и <год>.
3. Связи: входы, от которых зависит <показатель>.
4. Значения этих входов за оба года.
5. Изменения входов между годами.
6. Вывод.

- Шаг 2 — `get_values` по ID показателя за оба года. Если год сравнения не назван («почему просел DSCR в 2027») — сравни с предыдущим годом горизонта и напиши в «Оговорках», с каким годом сравнили. Если не назван и сам год — один вопрос о годе.
- Шаг 3 — `trace_dependencies` за более поздний год.
- Шаг 4 — `get_values` по входам из шага 3 (до 10 ближайших по глубине) за оба года.
- Шаг 5 — `derive pct_change` для входов, которые изменились: `a` — значение за ранний год, `b` — за поздний.
- Пересчёт (`run_scenarios`) в этой ветке не нужен.

Вывод: входы с наибольшим относительным изменением и направление их влияния. В «Оговорках» — обязательно: «изменения входов совпали по времени с изменением показателя; это не разложение вклада каждого входа». Если изменились только числа, заданные прямо в расчётных листах (входы модели не менялись), — так и скажи.

## Ошибки и что делать

| Код | Что делать |
| --- | --- |
| `skill_required` | Ты вызвал `trace_dependencies`, не прочитав этот skill (или он ушёл из контекста при сжатии истории). Прочитай `/skills/sensitivity-drivers/SKILL.md` и повтори вызов. |
| `missing_input` | Не повторяй вызов с теми же аргументами. Год — из запроса; если там нет — шаг `blocked` и вопрос. Не названный сдвиг — не вопрос: правило ±10 %. |
| `invalid_args` у `derive` | Эластичность не определена при базе 0 — исключи этот драйвер и скажи об этом в «Оговорках». |
| `limit_exceeded` | Рейтинг по уже посчитанным драйверам, остальные — в «Оговорках». |
| `no_values` | Это заголовок раздела — вернись к сопоставлению. |

## Ответ

Разделы — по правилам оформления ответа (`economic-answer`).

Ветка А:
- **Вывод** — какой драйвер сильнее всего влияет на показатель и насколько.
- **Ключевые цифры** — строка на драйвер в порядке рейтинга: драйвер, база, значения показателя при −N % и +N %, эластичность.
- **Анализ** — направление влияния каждого драйвера и порядок по силе; отношения эластичностей («в 3 раза сильнее») не пиши — их нет в результатах.
- **Где в модели** — путь «драйвер → промежуточные выходы → показатель».
- **Оговорки** — сдвиг ±N % и выбран ли он по умолчанию; эластичность посчитана по двум точкам и верна для небольших сдвигов; драйверы, не вошедшие в рейтинг, и почему; оговорки `trace_dependencies`.

Ветка Б:
- **Ключевые цифры** — показатель за оба года и изменение; входы с наибольшим изменением, их значения и изменение в %.
- **Где в модели** — путь «вход → промежуточные выходы → показатель».
- **Оговорки** — с каким годом сравнили; «не разложение вклада».

Пример вывода ветки А (числа условные): «Сильнее всего EBITDA 2026 зависит от цены метанола: эластичность 1,8 против 0,6 у курса».
