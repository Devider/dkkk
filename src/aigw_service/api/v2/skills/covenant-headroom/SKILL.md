# Запас по ковенантам и точка пробоя

Применяй, когда в запросе есть показатель-ковенант (DSCR, ICR, LLCR, Debt/EBITDA, Net Debt/EBITDA) и вопрос о запасе до порога, о пробое порога или о стресс-тесте.

Не этот skill:
- «как изменится DSCR при цене от 300 до 500» без порога и без вопроса о запасе — сценарная сетка (`scenario-analysis`);
- «какой должна быть цена, чтобы DSCR = 1,2» без сетки и без вопроса о запасе — подбор под цель (`target-seeking`).

Если в запросе есть и сетка, и порог («DSCR при падении цены на 10–30 %, при какой цене DSCR = 1,2, хватает ли запаса»), работает этот skill.

Направление ковенанта и трактовка показателей — в справочнике `/skills/covenant-headroom/references/covenants.md`. Прочитай его через `read_file`, если не уверен, «не ниже» или «не выше» ограничение для показателя.

## Шаблон плана

Образец шагов — формулируй их под запрос, не копируй текст дословно. Шаги 3–5 добавляй, только если в запросе есть драйвер и диапазон стресса.

1. Метрики и пороги: сопоставить <показатели> и <драйвер>; порог и направление — из запроса.
2. База: <показатели> и <драйвер> в <год>; запас базы до порога.
3. Стресс-сетка: <показатель> в <год> при <драйвер> от <начало> до <конец>.
4. Точка пробоя: значение <драйвер>, при котором <показатель> = <порог>.
5. Запас прочности: на сколько % <драйвер> может отклониться от базы до пробоя.
6. Вывод.

## Шаг 1. Метрики и пороги

- Один вызов `resolve_terms`: показатели-ковенанты — `role: output`, драйвер — `role: input`.
- Уверенность `high` — бери первого кандидата и не спрашивай о выборе показателя. Если в модели есть и обычный, и LTM-вариант, бери ближайший к словам пользователя и назови выбранный в «Оговорках».

**Порог — только из сообщения пользователя.** Порог ковенанта задан в кредитной документации клиента, в модели его нет. Не подставляй «типовой» или «обычный» порог, не бери порог из справочника или из своих знаний и не предлагай число в вопросе.

- Порог не назван ни для одного показателя — шаг «Метрики и пороги» в `blocked` с причиной «не указан порог», расчётов не делай. Ответ — один вопрос без разделов: «Какой порог по <показатель> установлен в кредитной документации?».
- Порог назван только для части показателей — считай их, а по остальным в «Оговорках» напиши, что порог не указан и запас не считался.

**Направление** — из справочника: DSCR, ICR, LLCR — «не ниже» (`direction: min`); Debt/EBITDA, Net Debt/EBITDA — «не выше» (`direction: max`). Если пользователь назвал направление сам («не более 3,5»), бери его.

**Год** — только из запроса. Нет года — шаг базы в `blocked` с причиной «не указан год», один вопрос о годе. Не бери «текущий» или последний год модели.

## Шаг 2. База и запас базы

- `get_values` по ID показателей и драйвера за год.
- Запас базы — `derive`, операция `headroom`: `a` — значение показателя из `get_values`, `threshold` — порог из запроса, `direction` — по направлению. Результат: абсолютный запас и запас в % от порога; отрицательный запас — ковенант нарушен уже в базе.

Запас не считай в уме — только `derive`.

## Шаг 3. Стресс-сетка

`run_scenarios` по драйверу — по правилам сетки из `scenario-analysis`:
- абсолютный диапазон — как в запросе; относительный («падение на 10–30 %») — от базы драйвера из шага 2: `min` = база × 0,7, `max` = база × 0,9;
- шаг не назван — не спрашивай: сетка из 5 точек, `step` = (`max` − `min`) / 4, точки сетки — в «Оговорках»;
- в `outputs` — все показатели-ковенанты с порогом.

**Нет драйвера или диапазона** («хватит ли запаса по DSCR в 2026, порог 1,2») — шаги 3–5 в план не включай и диапазон не придумывай. Ответ — запас базы; в «Оговорках» предложи назвать драйвер и диапазон для стресс-теста.

## Шаг 4. Точка пробоя

`derive`, операция `crossing`: `points` — пары из результата сетки (`x` — значение драйвера, `y` — значение показателя), `threshold` — порог из запроса. Числа передавай так, как они указаны в результате `run_scenarios`.

- Порог пересечён — результат даёт значение драйвера в точке пробоя (линейная интерполяция между соседними точками сетки).
- Порог не пересечён — `derive` вернёт ближайшую к порогу точку. Вывод: «в диапазоне <начало–конец> порог не пробивается; ближе всего — <показатель> = … при <драйвер> = …». Сетку без просьбы пользователя не расширяй.

## Шаг 5. Запас прочности драйвера

`derive`, операция `pct_change`: `a` — база драйвера (шаг 2), `b` — точка пробоя (шаг 4). Результат — на сколько процентов драйвер может отклониться от базы до нарушения ковенанта. Без точки пробоя шаг не выполняй.

## Ошибки и что делать

| Код | Что делать |
| --- | --- |
| `missing_input` | Не повторяй вызов с теми же аргументами. Недостающее — из запроса; если там нет — шаг `blocked` и один вопрос. |
| `invalid_args` у `derive` («числа не найдены») | Передай число ровно так, как оно указано в результате или в сообщении пользователя; порог — только из сообщения. |
| `bad_units` | Сверь единицы: коэффициенты — «раз», доли и проценты не смешивай. |
| `invalid_args` про год | Скажи, за какие годы есть значения, и спроси год. |
| `no_values` | Это заголовок раздела — вернись к сопоставлению и выбери другого кандидата. |

## Ответ

Разделы — по правилам оформления ответа (`economic-answer`). Для запроса о ковенантах:

- **Вывод** — хватает ли запаса и при каком значении драйвера ковенант нарушается; что это значит для кредитора.
- **Ключевые цифры** — база показателя, порог, запас (абсолютный и в % от порога), значения показателя по точкам сетки, точка пробоя, запас прочности драйвера.
- **Анализ** — как быстро показатель приближается к порогу по сетке; нарушен ли ковенант уже в базе.
- **Оговорки** — обязательно: порог взят из запроса; направление ковенанта; выбранный вариант показателя (например, LTM), если был выбор; шаг сетки по умолчанию и её точки; точка пробоя получена линейной интерполяцией между точками сетки.

Пример вывода (числа условные): «Запаса по DSCR 2026 хватает: 1,45 против порога 1,2. Ковенант нарушается при цене метанола 318 USD/т — на 20,5 % ниже базы».
