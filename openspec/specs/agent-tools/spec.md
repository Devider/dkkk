# agent-tools Specification

## Purpose

Инструменты агента v2: адаптер доменных функций в инструменты модели, единый контракт вызова и результата, каталог и доступность инструментов, сопоставление терминов, доступ к движку пересчёта и вынос больших результатов.

## Requirements

### Requirement: AR-Q3 Изоляция фреймворка

Зависимость от LangChain и LangGraph SHALL ограничиваться агентным рантаймом и адаптером инструментов (`api/v2/`). В функциях логики инструментов (`tools.py`), смысловом слое и пакете движка (`excel_engine`) новые импорты LangChain и LangGraph MUST NOT появляться.

#### Scenario: Пакет движка без LangChain
- **WHEN** проверяются импорты всех модулей `excel_engine`
- **THEN** ни один из них не импортирует `langchain`, `langchain_core` или `langgraph`

#### Scenario: Домен без новых импортов фреймворка
- **WHEN** проверяются импорты `tools.py` и модулей смыслового слоя
- **THEN** набор импортов LangChain и LangGraph совпадает с зафиксированной базовой линией и не расширяется

#### Scenario: Доменная функция не знает об агенте
- **WHEN** доменная функция вызывается через инструмент агента
- **THEN** она получает только свои обычные аргументы и не получает объектов рантайма агента

### Requirement: ADR-5 Служебные аргументы скрыты от модели

Схема каждого инструмента, которую видит модель, SHALL содержать только аргументы, которые модель выбирает сама. Пользователь, сессия, путь к файлу и индекс модели SHALL браться из контекста хода, а не из аргументов вызова.

#### Scenario: В схемах нет служебных аргументов
- **WHEN** перечисляются схемы всех зарегистрированных инструментов
- **THEN** ни одна не содержит полей `user_id`, `session_id`, `thread_id`, `file_name`, `file_path` или ссылок на индекс модели

#### Scenario: Файл берётся из контекста пользователя
- **WHEN** модель вызывает расчётный инструмент в ходе пользователя A
- **THEN** расчёт выполняется по файлу пользователя A из контекста хода, а не по имени файла из аргументов модели

#### Scenario: Попытка передать служебный аргумент
- **WHEN** модель передаёт в вызов поле, которого нет в схеме инструмента (например, `user_id`)
- **THEN** это поле не доходит до доменной функции

### Requirement: ADR-5 Расчёт по ID индекса модели

Расчётные инструменты SHALL принимать входы и выходы модели в виде ID индекса модели. Адаптер SHALL переводить ID в канонические имена по индексу из контекста хода и вызывать доменную функцию с теми же аргументами, что и v1 для тех же показателей.

#### Scenario: ID переводятся в канонические имена
- **WHEN** модель вызывает расчётный инструмент с ID входа и ID выхода
- **THEN** доменная функция получает канонические имена этих показателей из индекса модели текущего файла

#### Scenario: Логика расчёта не меняется
- **WHEN** один и тот же расчёт выполняется через инструмент v2 и напрямую через доменную функцию с каноническими именами
- **THEN** результаты совпадают

### Requirement: ADR-5 Каталог инструментов

Каталог SHALL регистрировать каждый инструмент с признаком доступности (базовый — виден всегда, или открывается указанным skill) и признаком обращения к движку пересчёта. Агент SHALL получать базовый набор и набор инструментов skills из каталога, а не собирать их вручную.

#### Scenario: Базовые инструменты регистрируются
- **WHEN** каталог собирается при старте
- **THEN** в базовом наборе есть расчётные инструменты `run_scenarios` и `find_input_for_target` с признаком обращения к движку

#### Scenario: Инструмент skill не попадает в базовый набор
- **WHEN** инструмент зарегистрирован как открываемый skill
- **THEN** он есть в наборе инструментов skills и отсутствует в базовом наборе
