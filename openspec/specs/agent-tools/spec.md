# agent-tools Specification

## Purpose

Инструменты агента v2: адаптер доменных функций в инструменты модели, единый контракт вызова и результата, каталог и доступность инструментов, сопоставление терминов, доступ к движку пересчёта и вынос больших результатов.

## Requirements

### Requirement: AR-Q3 Изоляция фреймворка

Зависимость от LangChain и LangGraph SHALL ограничиваться агентным рантаймом и адаптером инструментов (`api/v2/`). В функциях логики инструментов (`tools.py`), смысловом слое и пакете движка (`excel_engine`) новые импорты LangChain и LangGraph MUST NOT появляться.

#### Scenario: Пакет движка без LangChain
- **WHEN** проверяются импорты всех модулей `excel_engine`
- **THEN** ни один из них не импортирует `langchain`, `langchain_core` или `langgraph`

#### Scenario: Домен без новых импортов фреймворка
- **WHEN** проверяются импорты `tools.py` и модулей смыслового слоя
- **THEN** набор импортов LangChain и LangGraph совпадает с зафиксированной базовой линией и не расширяется

#### Scenario: Доменная функция не знает об агенте
- **WHEN** доменная функция вызывается через инструмент агента
- **THEN** она получает только свои обычные аргументы и не получает объектов рантайма агента

### Requirement: ADR-5 Служебные аргументы скрыты от модели

Схема каждого инструмента, которую видит модель, SHALL содержать только аргументы, которые модель выбирает сама. Пользователь, сессия, путь к файлу и индекс модели SHALL браться из контекста хода, а не из аргументов вызова.

#### Scenario: В схемах нет служебных аргументов
- **WHEN** перечисляются схемы всех зарегистрированных инструментов
- **THEN** ни одна не содержит полей `user_id`, `session_id`, `thread_id`, `file_name`, `file_path` или ссылок на индекс модели

#### Scenario: Файл берётся из контекста пользователя
- **WHEN** модель вызывает расчётный инструмент в ходе пользователя A
- **THEN** расчёт выполняется по файлу пользователя A из контекста хода, а не по имени файла из аргументов модели

#### Scenario: Попытка передать служебный аргумент
- **WHEN** модель передаёт в вызов поле, которого нет в схеме инструмента (например, `user_id`)
- **THEN** это поле не доходит до доменной функции

### Requirement: ADR-5 Расчёт по ID индекса модели

Расчётные инструменты SHALL принимать входы и выходы модели в виде ID индекса модели. Адаптер SHALL переводить ID в канонические имена по индексу из контекста хода и вызывать доменную функцию с теми же аргументами, что и v1 для тех же показателей. До запуска движка аргументы SHALL проверяться по индексу модели; при нарушении модель получает ошибку с кодом, а движок не запускается. Недостающие год, цель и диапазоны MUST NOT подставляться по умолчанию.

#### Scenario: ID переводятся в канонические имена
- **WHEN** модель вызывает расчётный инструмент с ID входа и ID выхода
- **THEN** доменная функция получает канонические имена этих показателей из индекса модели текущего файла

#### Scenario: Логика расчёта не меняется
- **WHEN** один и тот же расчёт выполняется через инструмент v2 и напрямую через доменную функцию с каноническими именами
- **THEN** результаты совпадают

#### Scenario: ID вне индекса
- **WHEN** расчётный инструмент вызван с ID, которого нет в индексе модели
- **THEN** модель получает `unknown_id`, движок не запускается

#### Scenario: Недостающие данные не подставляются
- **WHEN** в вызове нет года, цели или диапазона для входа
- **THEN** модель получает `missing_input` с названием недостающего, движок не запускается и никакое значение по умолчанию не используется

#### Scenario: Выход без значений
- **WHEN** выход из индекса не имеет значений ни за один год (заголовок раздела)
- **THEN** модель получает `no_values` с подсказкой взять другого кандидата, движок не запускается

#### Scenario: Год вне горизонта выхода
- **WHEN** запрошен год, за который у выхода нет значения
- **THEN** модель получает `invalid_args` с перечнем доступных лет, движок не запускается

#### Scenario: Некорректный диапазон
- **WHEN** у входа начало диапазона больше конца или шаг не больше нуля
- **THEN** модель получает `invalid_args`, движок не запускается

#### Scenario: Сетка больше лимита
- **WHEN** произведение числа точек по всем входам больше `AGENT_MAX_GRID`
- **THEN** модель получает `invalid_args` с посчитанным размером и подсказкой сузить сетку, движок не запускается

#### Scenario: Единицы диапазона не совпадают с базовым значением
- **WHEN** базовое значение входа выражено в долях, а диапазон похож на проценты (или наоборот)
- **THEN** модель получает `bad_units` с базовым значением входа, движок не запускается

### Requirement: ADR-5 Каталог инструментов

Каталог SHALL регистрировать каждый инструмент с признаком доступности (базовый — виден всегда, или открывается указанным skill) и признаком обращения к движку пересчёта. Агент SHALL получать базовый набор и набор инструментов skills из каталога, а не собирать их вручную.

#### Scenario: Базовые инструменты регистрируются
- **WHEN** каталог собирается при старте
- **THEN** в базовом наборе есть расчётные инструменты `run_scenarios` и `find_input_for_target` с признаком обращения к движку

#### Scenario: Чтения и derive в базовом наборе
- **WHEN** каталог собирается при старте
- **THEN** в базовом наборе есть `get_values`, `describe_model` и `derive` без признака обращения к движку

#### Scenario: Модель видит не больше 8 инструментов
- **WHEN** агент собирается с базовым набором каталога и встроенными инструментами плана и чтения файлов
- **THEN** модель видит не больше 8 инструментов (AR-Q6)

#### Scenario: Инструмент skill не попадает в базовый набор
- **WHEN** инструмент зарегистрирован как открываемый skill
- **THEN** он есть в наборе инструментов skills и отсутствует в базовом наборе

### Requirement: FR-7 Ошибка инструмента с кодом и подсказкой

Любая ошибка инструмента SHALL возвращаться модели как результат вызова в виде `{status: "error", error, code, hint}`, а не как необработанное исключение, — в том числе исключение, вылетевшее из инструмента во время хода агента. `code` SHALL быть одним из кодов справочника, `hint` SHALL называть следующий шаг. Текст исключения, traceback и внутренние пути MUST NOT попадать в `error` и `hint`. Исключение StopEvent GigaChat MUST NOT превращаться в конверт: оно прерывает ход (AR-Q11).

#### Scenario: Неизвестный ID индекса
- **WHEN** модель вызывает расчётный инструмент с ID, которого нет в индексе модели
- **THEN** результат вызова — конверт ошибки с кодом `unknown_id` и подсказкой вызвать `resolve_terms`, движок не запускается

#### Scenario: Непредвиденное исключение
- **WHEN** доменная функция падает с исключением, не известным справочнику
- **THEN** модель получает конверт с кодом `internal_error` и общей подсказкой, без текста исключения

#### Scenario: У каждой ошибки есть код и подсказка
- **WHEN** перебираются все ошибки, которые могут вернуть зарегистрированные инструменты
- **THEN** у каждой есть `code` из справочника и непустой `hint`

#### Scenario: Исключение в ходе агента
- **WHEN** во время хода инструмент падает с непредвиденным исключением
- **THEN** ход не прерывается, модель получает результат вызова — конверт `internal_error`, а полный traceback пишется в журнал

### Requirement: FR-7 Справочник кодов ошибок

Справочник SHALL содержать коды `invalid_args`, `unknown_id`, `ambiguous_term`, `term_not_found`, `no_values`, `bad_units`, `missing_input`, `engine_unavailable`, `engine_timeout`, `plan_required`, `limit_exceeded`, `cancelled`, `internal_error`; у каждого — подсказка по умолчанию, говорящая модели, что делать дальше. Инструмент MAY уточнить подсказку для конкретного случая.

#### Scenario: Подсказка по умолчанию
- **WHEN** ошибка создаётся только с кодом
- **THEN** её `hint` — подсказка этого кода из справочника

#### Scenario: Неизвестный код отклоняется
- **WHEN** код ошибки не входит в справочник
- **THEN** конверт не создаётся (ошибка разработки)

### Requirement: FR-7 Классификация результатов расчёта v1

Статусы и тексты расчётных функций v1 (`OK`, `WARNING`, `ERROR`) SHALL переводиться в конверт без правки расчётного кода: известные ошибки — в соответствующий код, нераспознанная ошибка — в `internal_error`. Результат подбора без найденных сценариев SHALL быть успехом с оговоркой, а не ошибкой.

#### Scenario: Не хватает входных данных
- **WHEN** расчёт возвращает ошибку «не указаны входные параметры» или «не удалось определить год»
- **THEN** модель получает код `missing_input`

#### Scenario: Строка без значений
- **WHEN** расчёт не находит ячейку выхода или входа для показателя из индекса
- **THEN** модель получает код `no_values` с подсказкой взять следующего кандидата

#### Scenario: Слишком большая сетка
- **WHEN** расчёт отклоняет сетку как слишком широкую
- **THEN** модель получает код `invalid_args` с подсказкой сузить диапазон или увеличить шаг

#### Scenario: Сбой движка
- **WHEN** расчёт падает из-за LibreOffice (UNO-мост, запуск `soffice`)
- **THEN** модель получает код `engine_unavailable`

#### Scenario: Цель не достигнута
- **WHEN** подбор входов не нашёл сценариев, дающих цель
- **THEN** результат — успех с оговоркой «цель не достигнута», а не ошибка

### Requirement: ADR-5 Единый конверт результата

Успешный результат каждого инструмента SHALL иметь вид `{status: "ok", result, data, numbers, notes, hint, ref}`: `result` — сводка на русском, `data` — компактные структурированные данные, `numbers` — список `{value, label, unit}` с числами результата, `notes` — оговорки. Серверные пути к файлам MUST NOT попадать в `data`.

#### Scenario: Сценарная сетка в конверте
- **WHEN** `run_scenarios` завершается успешно
- **THEN** конверт содержит сводку, таблицу сценариев в `data` и значения выходов по сценариям в `numbers` с подписями

#### Scenario: Значения сетки в numbers
- **WHEN** `run_scenarios` завершается успешно
- **THEN** каждое значение входа из сетки есть в `numbers` один раз с подписью входа, после минимумов и максимумов выходов

#### Scenario: Подбор под цель в конверте
- **WHEN** `find_input_for_target` находит сценарии
- **THEN** `numbers` содержит найденные значения входов и значение выхода, `data` — найденные сценарии

#### Scenario: Серверные пути скрыты
- **WHEN** доменный результат содержит пути к сохранённым файлам
- **THEN** в конверте этих путей нет

### Requirement: FR-6 Явное сопоставление терминов

Инструмент `resolve_terms` SHALL принимать термины пользователя с ролью (вход или выход модели) и возвращать по каждому термину кандидатов из индекса модели `{id, name, score}` и уровень уверенности `high` или `low`. Первым кандидатом SHALL идти выбор смыслового слоя. Уверенность SHALL быть `high`, только если выбор смыслового слоя совпадает с одним из лучших по лексическому сходству имён индекса. Смысловой слой при этом не меняется.

#### Scenario: Термин сопоставлен уверенно
- **WHEN** модель вызывает `resolve_terms` с термином, для которого выбор смыслового слоя входит в тройку лучших по лексическому сходству
- **THEN** результат термина содержит этого кандидата первым и `confidence: high`

#### Scenario: Термин сопоставлен неуверенно
- **WHEN** выбор смыслового слоя не входит в тройку лучших по лексическому сходству (например, английский термин при русских именах)
- **THEN** результат термина содержит выбор смыслового слоя первым, ещё до двух кандидатов и `confidence: low`

#### Scenario: Термин не найден
- **WHEN** для термина нет ни выбора смыслового слоя, ни кандидата с ненулевым сходством
- **THEN** результат этого термина — `term_not_found` с подсказкой переформулировать, остальные термины вызова сопоставляются как обычно

#### Scenario: Роль учитывается
- **WHEN** термин передан с ролью `output`
- **THEN** все его кандидаты — выходы модели, а не входы

### Requirement: FR-6 Устойчивость сопоставления

Сбой одного термина MUST NOT ронять сопоставление остальных. Временная недоступность модели из-за ограничения частоты запросов SHALL повторяться с паузой.

#### Scenario: Смысловой слой падает на одном термине
- **WHEN** смысловой слой падает при обработке списка терминов
- **THEN** инструмент повторяет сопоставление по одному термину, и термины, которые разрешаются по отдельности, получают кандидатов

#### Scenario: Ограничение частоты запросов
- **WHEN** GigaChat отвечает на вызов смыслового слоя ограничением частоты (HTTP 429)
- **THEN** вызов повторяется с паузой, и модель получает результат, а не ошибку, если повтор успешен

### Requirement: FR-6 Сопоставленные термины в состоянии

Результат `resolve_terms` SHALL сохраняться в состоянии агента как соответствие «термин → `{id, name, confidence}`» по первому кандидату, чтобы последующие шаги и ходы могли использовать его без повторного сопоставления.

#### Scenario: Термины попадают в состояние
- **WHEN** `resolve_terms` сопоставил термины
- **THEN** в состоянии агента есть `resolved_terms` с этими терминами, их ID, каноническими именами и уверенностью

#### Scenario: Повторное сопоставление дополняет состояние
- **WHEN** в ходе вызывается `resolve_terms` для новых терминов
- **THEN** новые термины добавляются к уже сопоставленным, прежние не теряются

### Requirement: FR-6 Точность не ниже v1

Доля правильно сопоставленных параметров через `resolve_terms` SHALL быть не ниже, чем у v1 на том же наборе запросов эталона.

#### Scenario: Сравнение с v1 на эталоне
- **WHEN** скрипт оценки прогоняет выборку эталона Methanex через `resolve_terms` и через анализатор v1 на исходных запросах
- **THEN** per-param accuracy `resolve_terms` по первому кандидату не ниже v1 на запросах, где оба отработали

### Requirement: FR-11 Недостижимая цель — результат анализа

Если подбор входов не нашёл сценариев, дающих цель, инструмент SHALL возвращать успех с признаком `reachable: false`, ближайшей найденной точкой (значения входов и выхода) и оговоркой. Найденная цель SHALL помечаться `reachable: true`.

#### Scenario: Цель достигнута
- **WHEN** подбор находит сценарии, дающие цель в пределах допуска
- **THEN** результат — успех с `reachable: true` и найденными значениями входов

#### Scenario: Цель недостижима
- **WHEN** ни один проверенный сценарий не даёт цель в пределах допуска
- **THEN** результат — успех с `reachable: false`, ближайшей точкой в данных и числах результата и оговоркой «цель не достигнута»

### Requirement: AR-Q8 Конкурентность движка

Расчёты одной сессии SHALL выполняться по одному, даже если модель или параллельные ходы запросили несколько расчётов одновременно. Число одновременных расчётов в сервисе SHALL ограничиваться пулом процессов размера `AGENT_CALC_WORKERS`; лишние расчёты ждут свободного места.

#### Scenario: Два расчёта одной сессии
- **WHEN** в одной сессии одновременно запускаются два расчёта
- **THEN** второй начинается только после завершения первого

#### Scenario: Расчёты разных сессий
- **WHEN** две сессии одновременно запускают по расчёту и в пуле есть два места
- **THEN** расчёты идут параллельно

#### Scenario: Пул заполнен
- **WHEN** расчётов запрошено больше, чем мест в пуле
- **THEN** одновременно выполняется не больше `AGENT_CALC_WORKERS`, остальные ждут и выполняются после

### Requirement: AR-Q9 Event loop не блокируется

Пересчёт книги в LibreOffice SHALL выполняться в отдельном процессе, а не в потоке или на event loop сервиса, чтобы сервис отвечал на другие запросы во время расчёта. Чтение книги (построение индекса модели) и синхронные инструменты чтения SHALL выполняться в рабочем потоке, а не на event loop.

#### Scenario: Сервис отвечает во время расчёта
- **WHEN** идёт пересчёт книги
- **THEN** задержка event loop сервиса не превышает 1 секунды

#### Scenario: Чтение не блокирует event loop
- **WHEN** выполняется `get_values`, `describe_model`, `derive` или построение индекса модели
- **THEN** работа идёт в рабочем потоке, а event loop в это время обслуживает другие корутины

### Requirement: ADR-6 Таймаут расчёта без сирот

Расчёт дольше `AGENT_CALC_TIMEOUT` SHALL прерываться: модель получает `engine_timeout`, процессы этого расчёта, включая `soffice`, завершаются, пул пересоздаётся и принимает следующие расчёты. Сбой пула SHALL возвращаться как `engine_unavailable`.

#### Scenario: Зависший расчёт
- **WHEN** расчёт не завершается за `AGENT_CALC_TIMEOUT`
- **THEN** модель получает `engine_timeout` с подсказкой сузить сетку, и после этого в системе не остаётся процессов `soffice` этого расчёта

#### Scenario: Работа после таймаута
- **WHEN** после таймаута запускается новый расчёт
- **THEN** он выполняется в пересозданном пуле и завершается успешно

#### Scenario: Воркер пула упал
- **WHEN** процесс воркера аварийно завершается во время расчёта
- **THEN** модель получает `engine_unavailable`, а пул пересоздаётся для следующих расчётов

### Requirement: AR-Q6 Вынос результата длиннее порога

Если сериализованный конверт успешного результата инструмента длиннее порога `AGENT_RESULT_MAX_CHARS` (символы JSON, по умолчанию 1500), полный конверт SHALL сохраняться в хранилище результатов по пути `/results/<ход>/<вызов>.json`, а модель SHALL получать компактный конверт: `status`, `result`, `notes`, `hint`, `numbers` и `ref` — путь к полному результату. Структурированные данные `data` MUST NOT попадать в компактный конверт. Ни один результат доменного инструмента (все, кроме `read_file` и `write_todos`, которые результатов расчёта не возвращают) в сообщениях модели MUST NOT быть длиннее порога: если компактный конверт не помещается, урезается список `numbers` с конца, затем сводка `result`; урезание отмечается в `notes`. Числа сценарной сетки SHALL идти по важности: сначала минимум и максимум каждого выхода, затем остальные. Полный результат SHALL читаться инструментом `read_file` по `ref`, по частям через `offset` и `limit`. Результат не длиннее порога и конверт ошибки SHALL отдаваться без выноса и без `ref`. Для каждого вызова доменного инструмента, который дошёл до инструмента и вернул конверт (в том числе из кэша сессии), в состоянии хода SHALL сохраняться запись с инструментом, статусом, кодом ошибки, сводкой, `ref` и полным списком `numbers`.

#### Scenario: Большая сценарная сетка
- **WHEN** `run_scenarios` возвращает сетку, конверт которой длиннее порога
- **THEN** в сообщении модели не больше `AGENT_RESULT_MAX_CHARS` символов: сводка, минимум и максимум каждого выхода в `numbers` и `ref`, без таблицы `data`

#### Scenario: Полный результат по ссылке
- **WHEN** модель вызывает `read_file` с путём из `ref`
- **THEN** она получает полный конверт результата, включая `data` и все `numbers`, и может дочитать длинный файл через `offset`

#### Scenario: Короткий результат не выносится
- **WHEN** конверт результата не длиннее порога
- **THEN** модель получает его целиком, `ref` нет, в хранилище результатов ничего не пишется

#### Scenario: Ошибка не выносится
- **WHEN** инструмент возвращает конверт ошибки
- **THEN** модель получает `{error, code, hint}` целиком, без `ref`

#### Scenario: Компактный конверт не помещается
- **WHEN** сводка и все числа результата вместе длиннее порога
- **THEN** в сообщение попадает начало списка `numbers`, в `notes` — пометка, что полный список в `ref`, а сообщение не длиннее порога

#### Scenario: Полные числа хода в состоянии
- **WHEN** результат вынесен и модель видит только часть `numbers`
- **THEN** запись этого вызова в состоянии хода содержит полный список `numbers` и `ref`

#### Scenario: Повтор из кэша
- **WHEN** расчёт с вынесенным результатом повторяется и отдаётся из кэша сессии
- **THEN** модель получает тот же компактный конверт с тем же `ref`, по которому читается полный результат, а запись вызова попадает в состояние текущего хода

### Requirement: AR-Q7 Изоляция вынесенных результатов

Хранилище вынесенных результатов SHALL разделяться по пользователю: пространство записи и чтения SHALL определяться `user_id` из контекста запроса, а не путём из аргументов модели. Пользователь MUST NOT читать результат другого пользователя ни по точному `ref`, ни при том же `x-session-id`, ни через относительные сегменты пути.

#### Scenario: Свой результат читается
- **WHEN** модель в ходе пользователя A читает `ref`, полученный в ходе того же пользователя
- **THEN** `read_file` возвращает полный результат

#### Scenario: Чужой результат не читается
- **WHEN** в ходе пользователя B с тем же `x-session-id` модель читает `ref` из результата пользователя A
- **THEN** `read_file` отвечает, что файл не найден, и содержимое результата A в ответ не попадает

#### Scenario: Путь не выбирает пространство
- **WHEN** модель передаёт в `read_file` путь `/results/` с сегментами `..` или с чужим `user_id` в пути
- **THEN** чтение идёт только в пространстве текущего пользователя, и чужой результат не находится

### Requirement: ADR-9 Производные числа считает derive

Инструмент `derive` SHALL считать производные числа без движка пересчёта: разницу, % изменения, запас до порога, точку пересечения порога и эластичность. Результат SHALL быть успешным конвертом, где каждое производное число лежит в `numbers` с подписью и единицами. Поэтому его, как и любой результат инструмента, видно в `step_results` хода (FR-13).

#### Scenario: Разница
- **WHEN** `derive` вызван с операцией «разница» для чисел `a` и `b` в одних единицах
- **THEN** в `numbers` есть `b − a` в тех же единицах

#### Scenario: Процент изменения
- **WHEN** `derive` вызван с операцией «% изменения» от `a` к `b`, `a ≠ 0`
- **THEN** в `numbers` есть `(b − a) / |a| · 100` с единицей `%`

#### Scenario: Запас до порога
- **WHEN** `derive` вызван с операцией «запас до порога» для значения `a`, порога `t` и направлением «не выше» (или «не ниже»)
- **THEN** в `numbers` есть абсолютный запас `t − a` (для «не ниже» — `a − t`) в единицах `a` и запас в % от `|t|`

#### Scenario: Порог нарушен
- **WHEN** абсолютный запас до порога отрицательный
- **THEN** результат успешный, запас отрицательный, а в `notes` есть оговорка «порог нарушен»

#### Scenario: Точка пересечения порога
- **WHEN** `derive` вызван с операцией «точка пересечения» для точек `{x, y}` и порога `t`, и между соседними по `x` точками `y − t` меняет знак
- **THEN** в `numbers` есть `x` первого пересечения, найденный линейной интерполяцией на этом отрезке, в единицах `x`

#### Scenario: Порог не пересекается
- **WHEN** у всех точек `y − t` одного знака
- **THEN** результат успешный, без точки пересечения, с оговоркой «порог не пересекается в диапазоне» и ближайшей к порогу точкой

#### Scenario: Эластичность
- **WHEN** `derive` вызван с операцией «эластичность» для точек `(x1, y1)` и `(x2, y2)`, где `x1 ≠ x2`, `x1 ≠ 0` и `y1 ≠ 0`
- **THEN** в `numbers` есть `((y2 − y1) / y1) / ((x2 − x1) / x1)` без единиц

#### Scenario: Деление на ноль
- **WHEN** у операции нулевой знаменатель (базовое значение `0` для % изменения, совпадающие `x` для эластичности)
- **THEN** модель получает `invalid_args` с объяснением, результат не считается

#### Scenario: Разные единицы
- **WHEN** у операндов разницы, запаса или пересечения разные известные единицы
- **THEN** модель получает `bad_units` с единицами операндов; `derive` единицы не пересчитывает

#### Scenario: Движок не запускается
- **WHEN** вызывается `derive`
- **THEN** пересчёт книги не выполняется и вызов не занимает место в пуле движка

### Requirement: ADR-9 Операнды derive только из источников

Каждый операнд `derive` (значения, точки и порог) SHALL быть найден среди источников FR-13: чисел результатов инструментов этого хода, чисел выжимок прошлых ходов и чисел из сообщений пользователя. Операнд совпадает с источником, если равен ему с точностью до округления, с которым его передала модель. В расчёт SHALL идти значение найденного источника. Операнд не из источников MUST отклоняться.

#### Scenario: Операнд из результата инструмента
- **WHEN** модель передаёт `2.81`, а в `numbers` вызова этого хода есть `2.8134`
- **THEN** операнд принят, расчёт идёт по `2.8134`, а в `data` указано, какое значение источника использовано

#### Scenario: Операнд из сообщения пользователя
- **WHEN** пользователь написал «ковенант 3,5x», а модель передаёт порог `3.5`
- **THEN** операнд принят

#### Scenario: Операнд из прошлого хода
- **WHEN** число есть в выжимке прошлого хода, а в этом ходе его не пересчитывали
- **THEN** операнд принят

#### Scenario: Выдуманный операнд
- **WHEN** операнда нет ни в одном источнике
- **THEN** модель получает `invalid_args` со списком непринятых чисел и подсказкой получить их инструментом (`get_values` или расчётом); результат не считается

### Requirement: ADR-5 Значения показателей по ID

Инструмент `get_values` SHALL возвращать значения входов и выходов по ID индекса модели без пересчёта книги: за указанные годы, а без лет — за все годы с значением. Каждое значение SHALL быть в `numbers` с подписью «показатель, год» и единицами показателя, если они указаны в модели.

#### Scenario: Значения выхода за годы
- **WHEN** модель вызывает `get_values` с ID выхода и годами `2025`, `2026`
- **THEN** в `numbers` есть значения выхода за эти годы с единицами из модели

#### Scenario: Базовое значение входа
- **WHEN** модель вызывает `get_values` с ID входа без лет
- **THEN** в `numbers` есть базовые значения входа за все годы, у которых есть значение

#### Scenario: Год без значения
- **WHEN** за один из запрошенных годов у показателя нет значения
- **THEN** результат успешный, а этот год перечислен в `notes`

#### Scenario: Выход без значений
- **WHEN** ID выхода указывает на строку без значений (заголовок раздела)
- **THEN** модель получает `no_values` с подсказкой взять следующего кандидата

#### Scenario: Неизвестный ID
- **WHEN** ID нет в индексе модели
- **THEN** модель получает `unknown_id` с подсказкой вызвать `resolve_terms`

### Requirement: ADR-5 Описание модели

Инструмент `describe_model` SHALL без аргументов и без пересчёта возвращать карточку загруженной модели: горизонт (первый и последний год, число лет), число входов и выходов, группы выходов по типу показателя с числом показателей в каждой. Список выходов с ID и типом SHALL лежать в `data`.

#### Scenario: Карточка модели
- **WHEN** модель вызывает `describe_model`
- **THEN** сводка называет горизонт модели, число входов и выходов и группы выходов по типу, а `numbers` содержит эти числа

#### Scenario: Длинный список выходов
- **WHEN** список выходов не помещается в порог `AGENT_RESULT_MAX_CHARS`
- **THEN** модель получает сводку и `ref`, а полный список читается через `read_file`
