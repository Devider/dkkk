# agent-api Specification

## Purpose

HTTP-интерфейс сервиса для агента v2: выбор движка агента, неизменный контракт запросов и ответов, коды ошибок и изоляция пользователей на уровне API.

## Requirements

### Requirement: FR-20 Переключатель движка агента

Сервис SHALL обслуживать `/api/v1/invoke-agent` агентом v1 или v2 в зависимости от `AGENT_ENGINE` (`v1` по умолчанию). Переключение и откат SHALL выполняться изменением переменной окружения и перезапуском, без пересборки образа. При `AGENT_ENGINE=v1` поведение сервиса SHALL оставаться прежним. Интеграционные тесты API SHALL проходить на обоих значениях `AGENT_ENGINE`.

#### Scenario: По умолчанию работает v1
- **WHEN** `AGENT_ENGINE` не задан
- **THEN** `/invoke-agent` обрабатывает агент v1, как до появления v2

#### Scenario: Включён v2
- **WHEN** `AGENT_ENGINE=v2`
- **THEN** `/invoke-agent` обрабатывает агент v2, и ответ имеет тот же формат: ZIP с `txt_response.txt` и `generated/agent_output.xlsx`

#### Scenario: Откат без пересборки
- **WHEN** после работы на v2 переменная `AGENT_ENGINE` возвращена в `v1` и сервис перезапущен
- **THEN** запросы снова обрабатывает v1 тем же образом

#### Scenario: Неверное значение
- **WHEN** `AGENT_ENGINE` имеет значение, отличное от `v1` и `v2`
- **THEN** сервис не стартует и сообщает допустимые значения

#### Scenario: Интеграционные тесты на обоих движках
- **WHEN** `tests/integration/v1_api` запускаются при `AGENT_ENGINE=v1` и при `AGENT_ENGINE=v2`
- **THEN** оба прогона зелёные

### Requirement: FR-15 Контракт ответа API

`/api/v1/invoke-agent` при `AGENT_ENGINE=v2` SHALL отвечать так же, как v1: ZIP с `txt_response.txt` и `generated/agent_output.xlsx`, состав ZIP MUST NOT меняться; заголовки и тело запроса — без изменений. Трасса хода (план, статусы, сводки результатов) SHALL оставаться на сервере (журнал, Langfuse) и MUST NOT попадать в ответ. Если у пользователя нет загруженного файла, ответ SHALL быть 200 с текстом «загрузите модель». Второй запрос в тот же `thread_id = "{user_id}:{session_id}"`, пока идёт ход, SHALL сразу получать HTTP 409 с просьбой направить вопрос позже, не дожидаясь хода и не меняя состояние сессии. StopEvent GigaChat (HTTP 403 с маркером временной недоступности) при вызове модели агента или смыслового слоя SHALL прерывать ход без повтора и давать HTTP 503.

#### Scenario: ZIP того же состава
- **WHEN** при `AGENT_ENGINE=v2` пользователь с загруженной моделью отправляет вопрос
- **THEN** ответ 200 — ZIP ровно из `txt_response.txt` с текстом ответа и `generated/agent_output.xlsx`

#### Scenario: Нет загруженного файла
- **WHEN** при `AGENT_ENGINE=v2` пользователь без загрузки отправляет вопрос
- **THEN** ответ 200, в `txt_response.txt` — просьба загрузить модель, вызовов LLM нет

#### Scenario: Занятая сессия
- **WHEN** пока идёт ход сессии, приходит второй запрос с тем же `x-user-id` и `x-session-id`
- **THEN** второй запрос сразу получает 409 с просьбой направить вопрос позже, первый завершается обычным ответом, а запрос в другую сессию обрабатывается

#### Scenario: StopEvent GigaChat
- **WHEN** GigaChat отвечает 403 с маркером «temporarily unavailable due to technical reasons» на вызов модели агента или смыслового слоя
- **THEN** ход прерывается без повтора, клиент получает 503 с сообщением о временной недоступности модели; 403 без маркера не превращается в 503

#### Scenario: Интеграционные тесты API
- **WHEN** запускаются `tests/integration/v1_api`
- **THEN** они проходят без правок

### Requirement: AR-Q13 Журнал вызовов LLM и инструментов

При `AGENT_ENGINE=v2` на каждый вызов модели агента в журнал сервера SHALL писаться одна строка `LLM CALL` с `trace_id` (= `x-trace-id`), `turn_id`, номером вызова в ходе, временем вызова, токенами (prompt, completion, total — если модель их вернула), именами инструментов, которые модель вызвала, и кодом ошибки, если вызов завершился исключением. На каждый вызов инструмента SHALL писаться одна строка `TOOL CALL` с `trace_id`, `turn_id`, именем инструмента, временем, статусом (`ok` / `error`) и кодом ошибки из конверта результата. Текст исключения MUST NOT попадать в строки `LLM CALL` и `TOOL CALL` — только код (класс исключения или код конверта). Исключение после записи строки SHALL распространяться дальше без изменений: телеметрия не меняет ход и ответ.

#### Scenario: Строка на каждый вызов модели
- **WHEN** ход делает два вызова модели, первый из которых вызывает `resolve_terms`
- **THEN** в журнале две строки `LLM CALL` с номерами 1 и 2, одним `turn_id`, `trace_id` запроса, временем и токенами; в первой среди инструментов есть `resolve_terms`

#### Scenario: Строка на каждый вызов инструмента
- **WHEN** модель вызывает инструмент, и он возвращает конверт ошибки с кодом `unknown_id`
- **THEN** в журнале строка `TOOL CALL` с именем инструмента, статусом `error` и кодом `unknown_id`

#### Scenario: Ошибка вызова модели
- **WHEN** вызов модели завершается исключением (например, StopEvent)
- **THEN** в журнале строка `LLM CALL` с кодом ошибки без текста исключения, а исключение доходит до API как раньше (StopEvent → 503)

#### Scenario: Ход без LLM
- **WHEN** ход завершается без вызова модели (нет файла, неподдерживаемый язык)
- **THEN** строк `LLM CALL` и `TOOL CALL` нет

### Requirement: AR-Q13 Дерево хода в Langfuse

Когда Langfuse включён, ход SHALL уходить в self-hosted Langfuse одной трассой с `langfuse_session_id = thread_id`, `langfuse_user_id = user_id` и тегом `agent_engine=<v1|v2>` по выбранному движку. Для v2 трасса SHALL содержать дерево хода: узлы middleware графа агента, вызовы модели с токенами, вызовы инструментов и вложенные вызовы смыслового слоя внутри вызова инструмента. Ключи, сертификаты и путь к файлу пользователя MUST NOT попадать в метаданные трассы. Когда Langfuse выключен или недоступен, ход SHALL выполняться без трассы, с тем же ответом.

#### Scenario: Метаданные трассы
- **WHEN** при `AGENT_ENGINE=v2` и включённом Langfuse пользователь задаёт вопрос
- **THEN** у трассы хода `session_id` = `"{user_id}:{session_id}"`, `user_id` = `x-user-id` и тег `agent_engine=v2`; при `AGENT_ENGINE=v1` — те же поля и тег `agent_engine=v1`

#### Scenario: Вложенный вызов смыслового слоя
- **WHEN** модель вызывает `resolve_terms`, а он обращается к LLM смыслового слоя
- **THEN** вызов LLM смыслового слоя виден в той же трассе дочерним узлом вызова `resolve_terms`

#### Scenario: Дерево хода
- **WHEN** ход делает план, сопоставление и расчёт
- **THEN** в трассе есть узлы middleware, вызовы модели, `write_todos`, `resolve_terms`, расчётный инструмент и итоговый узел выжимки хода

#### Scenario: Langfuse выключен
- **WHEN** Langfuse выключен или handler недоступен
- **THEN** ход завершается тем же ответом, а в журнале есть строки `LLM CALL` и `TOOL CALL`
