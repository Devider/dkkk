Story S3.5 · FR-19 (владелец) · AR-Q5 (также; владелец S2.1) · FR-12 (зависит, не меняется) · ADR-2 · §8 №1, №8 · §11 «Активация» п. 2

## Why

Закрепление skills уже работает: `TurnContext` передаёт `SkillsMiddleware` закреплённые имена, если их текста нет в видимой части сессии, а сборка агента падает на неизвестном имени. Но список закреплённых skills зашит в код (`factory.py: DEFAULT_PINNED = ("economic-answer",)`). §11 «Активация» п. 2 называет закрепление конфигурацией основным путём на случай, если eval покажет, что GigaChat пропускает чтение skill (риск §16). Сейчас для этого пришлось бы менять код и пересобирать образ. Нужна переменная окружения, как у остальных параметров агента (AR-Q5).

## What Changes

- Новый параметр `AgentSettings.pinned_skills`, переменная `AGENT_PINNED_SKILLS`. Значение — имена skills через запятую, по умолчанию `economic-answer`. Пробелы вокруг имён и повторы убираются, порядок сохраняется. Пустое значение означает «ничего не закреплять».
- Переменная задаёт **весь** список (решение пользователя). `economic-answer` можно убрать, например для eval без закрепления. Тогда при сборке агента в журнал пишется предупреждение: структура ответа FR-12 без него не гарантируется.
- `AgentFactory` по умолчанию берёт список из настроек. `DEFAULT_PINNED` удаляется, аргумент `pinned_skills` остаётся для тестов.
- Неизвестное имя в `AGENT_PINNED_SKILLS` останавливает старт сервиса с этим именем: это проверка из S3.1, она срабатывает при сборке агента в `lifespan`.
- Закреплённые skills вместе должны помещаться в дословный хвост истории (`AGENT_SUMMARY_KEEP` × `AGENT_MAX_PROMPT_TOKENS`), иначе сервис не стартует. Без этого сжатие срабатывает на каждом вызове, и модель видит только часть закреплённых skills (найдено при реализации, design D5).
- Закреплённый skill с `metadata.include_tools` держит свои инструменты открытыми без `read_file`, в том числе после сжатия истории: `TurnContext` закрепляет его заново.
- README: строка `AGENT_PINNED_SKILLS` в таблице параметров агента.
- Тесты: разбор переменной, значение по умолчанию, пустой список, неизвестное имя при старте, предупреждение без `economic-answer`, закрепление второго skill с инструментом, неизменный контракт API.

**Вне рамок:** выбор skills потребителем API (запрещено §11: «потребитель API skills не передаёт»); закрепление на уровне пользователя или сессии; новые skills и правка текстов skills; метрика eval «нужный skill прочитан» и решение, какие skills закреплять на GigaChat (S5.1, в контуре); живой прогон на GigaChat (эпик 5); v1.

### Modified Capabilities

- `agent-skills`: новое требование FR-19 «Активация skill» (ADDED, владелец S3.5). Модель читает skill сама, а `AGENT_PINNED_SKILLS` закрепляет skills на все ходы; потребитель API skills не передаёт.
- `agent-platform`: AR-Q5 «Параметры агента в конфигурации» (MODIFIED). В перечень параметров добавлен `AGENT_PINNED_SKILLS` (`economic-answer`).

## Impact

- Изменяемые файлы:
  - `src/aigw_service/config/agent/config.py` — поле `pinned_skills` и разбор списка;
  - `src/aigw_service/api/v2/factory.py` — список по умолчанию из настроек, предупреждение без `economic-answer`, удаление `DEFAULT_PINNED`;
  - `tests/unit/v2/test_answer.py` — ссылка на `DEFAULT_PINNED` заменяется проверкой настроек;
  - `README.md` — таблица параметров.
- Новый тестовый файл `tests/unit/v2/test_pinned_skills.py`.
- `TurnContext`, `SkillsMiddleware`, `SkillToolGate`, проверка skills, API и формат ответа не меняются. Значение по умолчанию совпадает с нынешним, так что поведение сервиса без переменной то же.
- Каждый закреплённый skill добавляет свой текст в контекст сессии и расходует бюджет `AGENT_MAX_PROMPT_TOKENS`. Слой виден в строке `CONTEXT LAYERS` как `skill_text`.
