# Design

## Context

Мотивация — в proposal.md, требования — в `specs/agent-skills/spec.md` (FR-19) и `specs/agent-platform/spec.md` (AR-Q5). Опорные разделы спецификации: ADR-2 (закрепление через `SkillsMiddleware` из `deepagents`), §8 №1 и №8, §11 «Активация» п. 2.

Что уже есть:
- `factory.py`: `DEFAULT_PINNED = ("economic-answer",)` — значение по умолчанию аргумента `AgentFactory(pinned_skills=...)`. `build()` проверяет skills (`validate_skills`) и падает с `SkillsError("<name>: закреплённый skill не найден")`, если закреплённого имени нет в каталоге (S2.x, FR-12).
- `api/__init__.py:lifespan` при `AGENT_ENGINE=v2` вызывает `get_agent_v2()`, поэтому ошибка сборки останавливает старт, а не первый запрос (AR-Q15).
- `TurnContext.abefore_agent` кладёт в `state["pinned_skills"]` имена, текста которых нет в видимой части истории. `before_model` делает то же после сжатия посреди хода. Сообщения закрепления `SkillsMiddleware` помечает `lc_source="pinned_skill"`, по этой метке `TurnContext` их и ищет. Код уже работает с любым списком, не только с одним skill.
- `deepagents` 0.7.29 `SkillsMiddleware` открывает инструменты из `metadata.include_tools` и для прочитанного, и для закреплённого skill, пока его текст в контексте (`middleware/skills.py`, докстринг класса). Значит `SkillToolGate` (S3.4) закреплённый skill-инструмент не отклоняет.
- `AgentSettings` (pydantic-settings 2.15) читает переменные `AGENT_*` через `validation_alias`. Поле-список pydantic-settings по умолчанию разбирает как JSON.
- Тесты читают значение по умолчанию через `DEFAULT_PINNED` (`test_answer.py::TestSkill::test_shipped_and_valid`).

## Goals / Non-Goals

**Goals:**
- Один источник списка закреплённых skills — настройки, с тем же значением по умолчанию, что сейчас.
- Ошибки конфигурации видны при старте: формат — при загрузке настроек, неизвестное имя — при сборке агента.

**Non-Goals:**
- Изменение `TurnContext`, `SkillsMiddleware`, `SkillToolGate` и проверки skills: механика закрепления уже есть.
- Перезагрузка списка без перезапуска: агент собирается один раз на процесс (`@cache get_agent_v2`), как и с остальными `AGENT_*`.

## Decisions

### D1. Формат переменной: имена через запятую

`pinned_skills: Annotated[tuple[str, ...], NoDecode]` с `validation_alias="AGENT_PINNED_SKILLS"` и `field_validator(mode="before")`. Строка делится по запятой, пробелы по краям имён убираются, пустые элементы и повторы отбрасываются, порядок первого вхождения сохраняется. Пустая строка даёт `()`. Если пришёл список или кортеж (конструктор в тестах), его обрабатывает та же нормализация.

Альтернатива — JSON-массив (`["economic-answer"]`, поведение pydantic-settings по умолчанию) — отвергнута. Кавычки в `.env` и `docker compose` легко сломать, а остальные `AGENT_*` — простые скаляры. Имя skill по формату Agent Skills не содержит запятых, так что разделитель однозначен.

Формат имени (`[a-z0-9-]`) при загрузке настроек не проверяется. Каталог skills на этом этапе неизвестен, а несуществующее имя всё равно отклоняет `build()` (D3). Двух проверок одного и того же не делаем.

### D2. Источник по умолчанию в `AgentFactory`

`pinned_skills: Sequence[str] | None = None`. Если передан `None`, берётся `APP_CONFIG.agent.pinned_skills`, как уже сделано для `plan_mode`. `DEFAULT_PINNED` удаляется, значение по умолчанию живёт только в `AgentSettings`. Тесты, которым нужен свой список, по-прежнему передают его явно (`test_skills.py` передаёт `()`).

### D3. Неизвестное имя и список без `economic-answer`

- Неизвестное имя — без изменений: `SkillsError` в `build()`, старт останавливается (сценарий FR-19 «Закреплённый skill отсутствует в каталоге»; тот же сценарий есть у FR-12).
- Список без `economic-answer` допустим (решение пользователя: переменная задаёт весь список). `build()` пишет `logger.warning` («AGENT_PINNED_SKILLS без economic-answer: структура ответа FR-12 не гарантируется»). Предупреждение пишется один раз на сборку, то есть при старте. Проверки структуры FR-12 (`structure_issues`) это не меняет: они в eval, не в рантайме.
- Отклонение от FR-12 «Skill закреплён … в каждом ходе». Требование выполняется при значении по умолчанию. Конфигурацию без `economic-answer` оператор выбирает сознательно (eval «без закрепления», замер §16). Поэтому FR-12 в этой story не меняется, а предупреждение в журнале делает выбор видимым. Альтернатива «запретить список без `economic-answer`» отвергнута пользователем.

Имя `economic-answer` вынесено в константу модуля `factory.py` (`ANSWER_SKILL`), чтобы предупреждение и тесты не дублировали строку.

### D4. Проверка «контракт API не меняется»

Тест уровня API (`httpx.AsyncClient(app=app_main)`, скриптовая модель) прогоняет один и тот же запрос с двумя списками закрепления и сравнивает статус, заголовки ответа и состав ZIP. Закреплённые skills лежат в state агента, а не в запросе. Поэтому проверяется и то, что в схеме запроса нет поля про skills.

### D5. Закреплённые skills должны помещаться в дословный хвост

Найдено при реализации задачи 3.2. Сжатие (§8 №7) идёт внутри вызова модели и оставляет дословный хвост `AGENT_SUMMARY_KEEP` × `AGENT_MAX_PROMPT_TOKENS`. Закрепление возвращается только перед следующим вызовом (`TurnContext.before_model` → `SkillsMiddleware`). Если закреплённые тексты вместе больше хвоста, хвост их не удержит. Тогда каждое сжатие отрезает один, его закрепляют заново и отрезается другой: сжатие идёт на каждом вызове, модель видит только часть закреплённых skills, а лишний вызов LLM для сводки повторяется. Пример: бюджет 12 000, хвост 3 600, два skill ≈ 2 600 токенов вместе с последним результатом чтения.

Решение (пользователь): `AgentFactory.build()` считает размер каждого закреплённого `SKILL.md` тем же приближённым счётчиком, что и сжатие (`context_tokens`), и при сумме больше хвоста бросает `SkillsError` с размерами. Старт останавливается так же, как при неизвестном имени. Альтернативы: предупреждение в журнале (зацикливание возможно в работе) и только документация — отвергнуты.

При настройках по умолчанию (хвост 9 000) помещаются любые два-три skill, но не все пять сразу (≈ 9 150). Вызов модели, на котором идёт само сжатие, уходит без отрезанных закреплений. Это принятое поведение `agent-loop` AR-Q6 «закрепляется снова до следующего вызова модели», и S3.5 его не меняет. Формулировка FR-19 приведена к нему.

## Risks / Trade-offs

- [Каждый закреплённый skill занимает бюджет запроса: сейчас 1,3–2,5 тыс. токенов на skill] → слой `skill_text` в `CONTEXT LAYERS` (S2.7) показывает расход. Верхнюю границу задаёт D5 — дословный хвост истории; числом skills список не ограничиваем.
- [Вызов, на котором идёт сжатие, обходится без отрезанных закреплений] → принятое поведение AR-Q6 (D5); со следующего вызова тексты снова в контексте.
- [Опечатка в имени останавливает старт] → так задумано (AR-Q15): лучше упасть при старте, чем молча работать без методики. Ошибка называет имя.
- [Закреплённый skill-инструмент открыт всегда, и модель может вызвать его не по делу] → это ожидаемое следствие закрепления. `TurnLimits` и `SkillToolGate` остаются в силе.

## Migration Plan

Значение по умолчанию совпадает с текущим, поэтому без переменной поведение не меняется. Откат — удалить переменную или вернуть `economic-answer`; нужен перезапуск, пересборка образа не нужна.
