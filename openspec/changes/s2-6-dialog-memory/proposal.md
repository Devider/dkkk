Story S2.6 · FR-10, FR-16 (владелец) · ADR-8 · AR-Q7 · §8 стек №20 · §9 «Слои контекста» (память диалога), «Состояние агента», «Правила» 1, 4, 5 · §12 «Сводка хода на сервере» · §14 сценарии U5, U8

## Why

Каждый ход v2 сейчас начинается с чистого листа: агент собран без checkpointer, поэтому план с шагом `blocked`, сопоставленные термины и цифры прошлого хода теряются. FR-10 требует, чтобы ответ пользователя на вопрос о недостающих данных продолжал тот же план, а FR-16 — чтобы уточнение («а если то же на 2027?») и вопрос по прошлому ответу («почему DSCR просел?») обходились без повторного сопоставления и пересчёта. ADR-8 задаёт механизм: checkpointer по `thread_id` и выжимка хода без LLM.

## What Changes

- Агент v2 собирается с checkpointer сервиса (`APP_CTX.agent_memory.checkpointer`, сейчас `MemorySaver`) — состояние сессии (`thread_id = "{user_id}:{session_id}"`, его уже передаёт `router.py`) сохраняется между ходами.
- `TurnSummary` (§8 №20): `after_agent` строит выжимку хода без LLM — вопрос, итог плана, результаты инструментов (статус, код, сводка, ключевые числа) — хранит последние 5 в `turn_summaries` и пишет в журнал сервера; `wrap_model_call` добавляет к системному промпту блок «Память диалога»: сопоставленные термины с ID, выжимки прошлых ходов, шаги `blocked`, ждущие ответа пользователя.
- `TurnContext` запоминает сообщение пользователя, с которого начался ход (граница хода для выжимки).
- Промпт плана: при шагах `blocked` прошлого хода — обновить их статус по ответу пользователя, а не строить план заново; ID из памяти диалога использовать без повторного `resolve_terms`.

**Вне рамок:** внешний checkpointer (Postgres / Pangolin) и переключатель `AGENT_CHECKPOINTER` (открытый вопрос §16); блокировка хода и HTTP 409 (S2.8, S4.2); сводка хода в Langfuse (S4.3); `step_results` и вынос крупных результатов в `/results/` (S1.6) — до неё выжимка строится по сообщениям-результатам хода; `SummarizationMiddleware` (S2.7); качество вопросов о недостающем и «не подставлять по умолчанию» на GigaChat — eval S5.1.
