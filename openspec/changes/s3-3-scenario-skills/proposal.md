## Why

Механика skills готова (S3.1), структура ответа закреплена (S3.2), но два самых частых запроса аналитика — подбор входа под цель и сценарная сетка — держатся только на общем системном промпте. Прогон S3.2 на GigaChat показал, что этого мало: модель подставляет год, которого нет в запросе, вызывает подбор без аргументов и спрашивает выбор показателя при однозначном термине. Методика этих двух сценариев (шаблон плана, правила аргументов, выход из типичных ошибок) должна жить в skills первой волны — без правки кода агента (FR-18, G4).

## What Changes

- Skill `api/v2/skills/target-seeking/`: «Какой должна быть X, чтобы Y = Z?» — шаблон плана «сопоставить → базовые значения → подбор → отклонение от базы → вывод», правила аргументов подбора (цель, год, входы, допуск — только из запроса), недостижимая цель (FR-11), типичные ошибки по кодам и формат разделов ответа.
- Skill `api/v2/skills/scenario-analysis/`: «Посчитай Y при X от a до b», «при падении на 10–30 %», точечный «а если X = 500» — шаблон «сопоставить → база (для относительных диапазонов) → сетка → изменения → вывод», перевод относительного диапазона в абсолютный от базового значения, сетка из одной точки, лимит сетки, единицы (доля / %), абсолютный диапазон в «Оговорках» (U3). Шаг сетки, не названный пользователем, не переспрашивается: сетка из 5 точек, точки сетки — в «Оговорках» (как требует U2: ход доводится без вопроса).
- В каждом skill — `evals.yaml` с примерами запросов, ожидаемым планом, инструментами и признаками ответа; модель его не читает.
- Тесты: оба skill валидны и видны в каталоге промпта; сквозной ход U3 на скриптовой модели с настоящим каталогом и middleware; сквозной ход подбора под цель (U1).
- Скрипт `scripts/eval/scenario_skills.py`: прогон запросов из `evals.yaml` обоих skills (прочитан нужный skill, вызваны ожидаемые инструменты, план с шагом базы, гигиена и структура ответа, время); режим `--scripted` без сети. Живой прогон на GigaChat и сравнение с v1 — в контуре.
- Логика агента (`api/v2/` вне `skills/`) не меняется — это и есть проверка FR-18. Единственная правка вне `skills/` — текст описания поля `step` в `run_scenarios`: сейчас он запрещает выбирать шаг и противоречит skill (design D6).

**Вне рамок:** `covenant-headroom`, `sensitivity-drivers` и `trace_dependencies` (S3.4); `point-what-if` и `set_inputs_and_recalc` (позже, §11); настройка `AGENT_PINNED_SKILLS` и закрепление этих skills (S3.5) — здесь их читает модель; полный eval-набор и метрики (S5.1); сравнение v1 / v2 по per-param accuracy и времени (S5.3, во внутреннем контуре).
