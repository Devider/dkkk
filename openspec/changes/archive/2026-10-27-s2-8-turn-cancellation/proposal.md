## Why

Ход v2 сейчас не ограничен по времени: медленная модель или длинная серия расчётов держит запрос и блокировку сессии сколько угодно, а клиент, закрывший соединение, всё равно ждёт до конца — движок и GigaChat работают впустую. AR-Q10 требует, чтобы таймаут хода `AGENT_TURN_TIMEOUT` (300 с) давал частичный ответ, AR-Q12 — чтобы разрыв соединения или таймаут останавливали ход после текущего вызова, не оставляя сирот `soffice` и не повреждая чекпоинт. Блокировка хода с HTTP 409 уже сделана в S4.2; эта story закрывает оставшуюся часть строки S2.8.

## What Changes

- **Дедлайн хода (AR-Q10).** `AgentV2` при старте хода ставит `RequestContext.deadline = now + AGENT_TURN_TIMEOUT` (по умолчанию 300 с). Новый middleware `Cancellation` (§8 №3) проверяет дедлайн перед каждым вызовом модели и перед каждым вызовом инструмента. Истёк дедлайн — инструмент не запускается и возвращает конверт `cancelled`, а следующий вызов модели становится последним, без инструментов, с указанием дать частичный ответ и оговоркой, что время хода истекло (тот же механизм последнего вызова, что у лимитов S2.5). Клиент получает обычный ответ HTTP 200.
- **Разрыв соединения (AR-Q12).** Роутер на время хода v2 ждёт сообщения `http.disconnect` от клиента и при разрыве поднимает флаг отмены в `RequestContext`. Флаг останавливает ход после текущего вызова: инструменты получают `cancelled`, а перед следующим вызовом модели ход завершается фиксированным сообщением без вызова LLM — ответ всё равно некому читать.
- **Ход не прерывается посреди вызова.** Текущий вызов модели или расчёт доводится до конца (расчёт ограничен своим `AGENT_CALC_TIMEOUT`, S1.5), поэтому чекпоинт остаётся согласованным: у каждого вызова инструмента есть результат, последнее сообщение — ответ агента; следующий ход в сессию работает как обычно.
- **Без сирот `soffice` (AR-Q12).** При остановке сервиса `lifespan` гасит пул движка (`EngineGate.shutdown`) — сейчас этого нет, и воркеры с `soffice` переживают процесс.
- **План (FR-8, уточнение).** При истёкшем времени хода `PlanCompletionGuard` принимает ответ сразу с разделом «Не выполнено», открытые шаги — `skipped` с причиной «Истекло время хода».
- Новая настройка `AGENT_TURN_TIMEOUT` в `config/agent` и README (AR-Q5).

**Вне рамок:** блокировка хода и HTTP 409 — сделаны в S4.2 (FR-15), здесь только проверяется, что после отмены сессия свободна; замер p50 / p90 из AR-Q10 — eval S5.1 / S5.3; прерывание вызова, который уже идёт (жёсткий таймаут поверх текущего вызова LLM); метрика исхода хода «частичный» — `Telemetry` S4.3; частичный ответ после исчерпания повторов LLM (остаётся HTTP 424, отмечено в S2.5); v1.
