Story S1.7 · FR-13 (уточнение; владелец — S4.1) · AR-Q9 (уточнение; владелец — S1.5) · ADR-5, ADR-9 · §10 «Каталог», §14 «Уровни» (`derive`)

## Why

Spike S0.2 показал: модель сама досчитывает производные числа — разницы, проценты изменения, запас до ковенанта. Такие числа не взяты ни из одного результата инструмента. По ADR-9 `derive` — обязательная пара к `AnswerGroundingGuard` (S4.1): без него guard будет отбраковывать честные вычисления модели, а сами вычисления никто не проверяет. Кроме того, в базовом наборе нет простых чтений. Чтобы показать базовое значение показателя или горизонт модели, агенту сейчас приходится запускать пересчёт. Это последняя незакрытая story слоя инструментов (E1); от неё зависит S3.4.

## What Changes

- **`derive` — арифметика над обоснованными числами (FR-13, ADR-9).** Новая чистая функция, движок не вызывает. Операции: разница, % изменения, запас до порога (абсолютный и в %, направление «не выше» / «не ниже»), точка пересечения порога (линейная интерполяция по точкам `{x, y}`), эластичность. Модель передаёт операнды значениями с подписью. `derive` проверяет, что каждое число есть в источниках FR-13: `numbers` вызовов этого хода (`step_results`), числа выжимок прошлых ходов, числа из сообщений пользователя. В расчёт идёт найденное значение источника, а не округление модели. Число не из источников → `invalid_args` с подсказкой получить его инструментом. Результат — обычный конверт: в `numbers` лежат производные числа с подписью и единицами, и guard S4.1 находит их в `step_results`.
- **`get_values` — значения показателей по ID.** Входы (базовые значения) и выходы за указанные годы (без лет — за все), с единицами из колонки «Ед. измерения». Без пересчёта, из индекса модели. Года без значения перечисляются в `notes`; выход без значений → `no_values`; неизвестный ID → `unknown_id`.
- **`describe_model` — карточка модели.** Горизонт (годы), число входов и выходов, группы выходов по «Тип показателя» с числом показателей. Список выходов с ID лежит в `data`; длинный результат выносится в `/results/` (S1.6).
- **Индекс модели расширяется.** К нему добавляются значения выходов по годам, единицы входов и выходов, тип выхода. Всё это читается тем же проходом openpyxl, что и сейчас.
- **Значения сетки — тоже источник.** `run_scenarios` добавляет в `numbers` значения входов сетки (каждое значение один раз, после минимумов и максимумов выходов). Так точку пересечения и ответ «при цене 300…» можно обосновать.
- **Каталог.** `get_values`, `describe_model` и `derive` входят в базовый набор без признака движка. Вместе с `write_todos`, `read_file`, `resolve_terms`, `run_scenarios`, `find_input_for_target` модель видит 8 инструментов (AR-Q6). Системный промпт: «производные числа считай через `derive`».
- **Чтения не блокируют event loop (AR-Q9, уточнение).** Инструменты чтения выполняются в рабочем потоке, как и построение индекса.

**Вне рамок:** `AnswerGroundingGuard` — проверка чисел ответа, перегенерация и снятие числа с оговоркой (S4.1). S4.1 переиспользует поиск источников, но правила сравнения чисел ответа уточняет сам. Skills `covenant-headroom` / `sensitivity-drivers` и пороги из текста skill как источник (S3.4). `trace_dependencies` и `set_inputs_and_recalc` (S3.3 / S3.4). Ссылки на результат по `call_id` (выбраны значения с проверкой). Пересчёт единиц (доли ↔ проценты, млн ↔ млрд): `derive` единицы не конвертирует. Чтение чисел из файлов `/results/` как источника. v1 и его `get_output_info` / `describe_outputs_sheet` не меняются.

### Modified Capabilities

- `agent-tools`: добавляются требования к `derive` (ADR-9: производные числа считает инструмент, операнды только из источников), `get_values` и `describe_model` (ADR-5: чтения по ID индекса). ## Impact

- Новые модули: `api/v2/tools/derive.py` (операции, единицы, конверт), `api/v2/tools/grounding.py` (сбор источников чисел из состояния и проверка операнда — переиспользует S4.1), `api/v2/tools/read_tools.py` (`get_values`, `describe_model`).
- Изменения: `tools/context.py` (`ModelIndex`: значения выходов, единицы, типы), `tools/index_builder.py` (единицы и типы в том же проходе), `tools/adapter.py` (состояние хода доступно инструменту для `derive`), `tools/calc_tools.py` (значения сетки в `numbers`), `tools/catalog.py`, `prompts/system.py`.
- Тесты: новые `tests/unit/v2/test_derive.py` (property-based, `hypothesis`), `tests/unit/v2/test_read_tools.py`; обновляются `test_tool_adapter.py`, `test_offload.py` (порядок `numbers`), `test_runtime.py` (набор базовых инструментов).
- Зависимости: `hypothesis` в dev-группе Poetry (если ещё нет). Поведение v1 и контракт HTTP API не меняются.
