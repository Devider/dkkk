# Design — S1.7 `derive`, `get_values`, `describe_model`

## Context

Мотивация — proposal.md. Что уже есть:

- `tools/adapter.py:build_tool` вызывает `ToolSpec.call(args, ctx)` в `asyncio.to_thread` или `ToolSpec.acall(args, ctx)` на event loop. `ctx` — это `runtime.context` (`ToolContext`): пользователь, путь к файлу, индекс. Состояния агента инструмент сейчас не видит. После вызова адаптер пишет запись в `step_results` с полными `numbers` (S1.6).
- `tools/context.py:ModelIndex` хранит ID → имя для входов и выходов, значения входов по годам (`input_values`) и годы выходов, у которых есть значение (`output_years`). Значений выходов, единиц и типов показателей в индексе нет.
- `tools/index_builder.py` строит индекс одним проходом openpyxl (`data_only=True`, кэшированные значения) через `build_mappings` → `create_input_mapping` / `create_output_mapping` из v1 `tools.py` (неизменяемые). `turn/registry.py` вызывает его в `asyncio.to_thread`.
- Значения выходов есть в `output_mapping[...]["values"]`, но `index_builder` оставляет из них только годы. Номер строки — `["row"]`. Колонки «Ед. измерения» (оба листа) и «Тип показателя» (Outputs) mapping не читает. В Methanex: 189 выходов, 462 входа; единицы `USD млн`, `%`, `количество раз…`; заглушка `[требуется заполнить]` встречается 32 раза. Значения с единицей `%` хранятся долями (`0.051`).
- v1 `get_output_info` и `describe_outputs_sheet` берут файл через `get_store_file(user_id)` и ищут показатель по имени через Jaccard. `describe_outputs_sheet` обёрнут в `@tool`.
- `TurnSummary` хранит в `turn_summaries` до 5 выжимок, в каждой — до 16 чисел `{label, value}`. История сообщений пользователя лежит в `state["messages"]` (checkpointer, ADR-8).
- Системный промпт уже требует «ничего не досчитывай сам» (FR-13), но инструмента для производных чисел нет.

## Goals / Non-Goals

**Goals:** модель получает производное число из инструмента, и оно обосновано так же, как любое другое (`step_results`). Выдуманный операнд не превращается в «обоснованный» результат `derive`. Базовые значения и карточка модели доступны без пересчёта. Модуль источников чисел переиспользуется в S4.1.

**Non-Goals:** проверка чисел готового ответа (S4.1); пересчёт единиц; пороги из текста skill (S3.4); числа из файлов `/results/` как источник.

## Decisions

### D1. Операнды — значения с проверкой по источникам (ADR-9, решение пользователя)

Операнд `derive` — это `{value, label}`. Порог и точки `{x, y}` передаются числами. Модуль `tools/grounding.py` собирает источники из состояния хода:

1. `numbers` всех записей `step_results` этого хода (полный список, даже если модель видела урезанный, S1.6);
2. `numbers` из `turn_summaries`;
3. числа из текста всех `HumanMessage` в `state["messages"]`. Разбор: `3,5` и `3.5`, пробел или неразрывный пробел как разделитель тысяч (`1 200`), знак, `%` и `x` после числа не мешают.

Каждый источник — `Source(value, label, unit)`. Операнд `v` совпадает с источником `s`, если `|v − s| ≤ min(0.5·10^(−d), 0.005·|s|)`, где `d` — число знаков после точки в кратчайшей записи `v`, или если `v == s`. Первая граница принимает округление модели (`2.81` для `2.8134`), вторая не даёт целому `3` совпасть с `2.6`. Из нескольких совпадений берётся ближайшее. В расчёт идёт `s.value`, единица — `s.unit`. В `data.operands` указано, какое значение источника использовано и с какой подписью.

Непринятые операнды перечисляются все сразу в одном `invalid_args`. Подсказка: «получи число инструментом (`get_values` или расчётом) и передай его так, как оно указано в результате». Доли и проценты не сопоставляются (`5.1` против `0.051` отклоняется), это видно из подсказки и описания инструмента.

API для S4.1: `collect_sources(state) -> list[Source]` и `match(value, sources) -> Source | None`. S4.1 может ужесточить или расширить правила для чисел ответа, не меняя `derive`.

*Альтернативы:* ссылки `call_id` + номер числа — отвергнуты пользователем (модель копирует длинный `tool_call_id`; нумерация урезанных `numbers` расходится с полной). Значения без проверки — тоже отвергнуты: выдуманный операнд стал бы «обоснованным» результатом.

### D2. Инструменту нужно состояние хода

У `ToolSpec` появляется флаг `needs_state: bool = False`. При нём адаптер передаёт третий аргумент — снимок `runtime.state` только для чтения (`MappingProxyType` верхнего уровня). Это `call(args, ctx, state)`. Вызов по-прежнему идёт в `asyncio.to_thread`. Служебное состояние в схеме модели не появляется (ADR-5).

Инструмент без аргументов (`describe_model`): langchain-core отбрасывает все аргументы вызова, в том числе внедрённый `runtime`, если у схемы нет полей. Поэтому для пустой схемы адаптер строит инструмент из сигнатуры `run(runtime: ToolRuntime[Any, Any])`. Модель по-прежнему видит пустую схему (найдено при реализации).

*Альтернатива:* класть источники в `ToolContext` — отвергнута. `RequestContext` собирается до хода и не знает о результатах, которые появляются в ходе.

### D3. Операции и единицы `derive`

Схема: `operation` (`difference` | `pct_change` | `headroom` | `crossing` | `elasticity`); `a`, `b` — операнды; `threshold`; `direction` (`max` — «не выше», `min` — «не ниже»); `points` — список `{x, y}`. Схема проверяет, какие поля нужны операции. Нехватка поля → `missing_input` с названием поля (как в контракте §10 п. 2).

| Операция | Формула | Единица результата |
| --- | --- | --- |
| `difference` | `b − a` | единица операндов |
| `pct_change` | `(b − a) / |a| · 100`; `a = 0` → `invalid_args` | `%` |
| `headroom` | `max`: `t − a`, `min`: `a − t`; в %: запас `/ |t| · 100`; `t = 0` → только абсолютный | единица `a`; `%` |
| `crossing` | точки сортируются по `x`; первый отрезок, где `(y − t)` меняет знак или равно 0; `x* = x1 + (t − y1)·(x2 − x1)/(y2 − y1)` | единица `x` |
| `elasticity` | `((y2 − y1)/y1) / ((x2 − x1)/x1)`; нулевой знаменатель → `invalid_args` | без единиц |

Отрицательный запас → `notes: «порог нарушен»`. Нет пересечения → успех, `notes: «порог не пересекается в диапазоне»`, в `numbers` — ближайшая к порогу точка (FR-11: «не достигнуто» — это результат, а не ошибка). Для `crossing` нужно не меньше 2 точек.

Единицы: у операнда единица источника, у числа из сообщения пользователя — `%`, если `%` стоит сразу после числа, иначе нет. Две разные известные единицы в `difference` / `headroom` (`a` и `t`) / `crossing` (все `y` и `t`) → `bad_units`. Неизвестная единица совместима с любой. Пересчёта нет. Разница двух `%`-долей остаётся в той же единице, и сводка `derive` называет её «в долях». Результат округляется только в `result` (до 4 значащих цифр). В `numbers` идёт полное значение: guard S4.1 сравнивает с тем же допуском.

Подписи `numbers` строятся из подписей источников, например «Запас до порога 3.5: Долг/EBITDA 2026». Тогда ответ и guard ссылаются на понятное число.

### D4. `get_values` и `describe_model` читают индекс, а не v1-функции — отклонение от §10 «Каталог»

*Отклонение от §10 «Каталог», колонка «Оборачивает»:* `get_values` и `describe_model` читают индекс модели (`ModelIndex`), а не вызывают `get_output_info` / `describe_outputs_sheet`. Причина: v1-функции находят файл по `user_id` через store и ищут показатель по имени (Jaccard), а инструмент v2 получает ID и путь из контекста хода. Значения те же (кэшированные значения листа), лишнего чтения файла нет.

§10 называет обёрнутыми `get_output_info` и `describe_outputs_sheet`. Вызывать их в v2 нельзя без правки. Они находят файл через `get_store_file(user_id)`, тогда как в v2 путь берётся из контекста хода. `get_output_info` ищет показатель по имени (Jaccard), а модель v2 передаёт ID: повторный поиск по имени мог бы вернуть другую строку. Нужные данные (кэшированные значения листов, те же, что читает `pandas` в v1) уже читаются при построении индекса. Поэтому:

- `ModelIndex` получает поля `output_values: Mapping[str, Mapping[int, float]]`, `units: Mapping[str, str]` (по ID входа и выхода; заглушка `[требуется заполнить]` и пустое значение пропускаются) и `output_types: Mapping[str, str]`. Существующие поля и порядок ID не меняются. Все новые поля имеют значения по умолчанию, поэтому старые конструкторы в тестах работают.
- `index_builder` сам открывает книгу (как `build_mappings`), передаёт строки в те же `create_input_mapping` / `create_output_mapping`, а единицы и тип берёт из тех же строк по колонкам заголовка («Ед. измерения», «Тип показателя») и `row` из mapping. Проход один, неизменяемый код не трогается.
- Единица `%` из книги в `numbers` подписывается как `доля`: значения хранятся долями (`0.051`), а `15 %` из сообщения пользователя — это проценты. Разные подписи не дают `derive` молча смешать долю и процент — получается `bad_units` (найдено при реализации, `ModelIndex.unit`). То же относится к значениям сетки `run_scenarios` (D5).
- `get_values(ids, years=None)`: ID с префиксом `IN` — вход, `OUT` — выход, иначе `unknown_id`. Числа: `"<имя>, <год>"` с единицей. Для единицы `%` в `notes` пишется «значения в долях: 0.05 = 5 %». Годы без значения → `notes`. Выход без значений вообще → `no_values`. Чтобы урезание `numbers` (S1.6) не вырезало целый показатель, ID обходятся по очереди, годы — по возрастанию.
- `describe_model()`: горизонт по годам выходов (объединение `output_years`), число входов и выходов, группы `output_types` с числом показателей. Строки без значений (заголовки разделов) не считаются показателями, а их число указывается отдельно. `data.outputs` — `[{id, name, type, unit}]`, только выходы со значениями. При 189 выходах результат длиннее порога и уходит в `/results/` (S1.6).

Оба инструмента синхронные (`call`) и идут в рабочем потоке (AR-Q9). Ввода-вывода у них нет, но их можно позже перевести на чтение файла, не меняя контракта.

*Альтернатива:* скопировать `get_output_info` / `get_outputs_business_summary` в `excel_engine` (как S0.7). Отвергнута: второе чтение файла через `pandas` на каждый вызов и поиск по имени вместо ID. Этот вариант остаётся, если S0.4 покажет расхождение кэшированных значений openpyxl и `pandas`, но обе библиотеки читают одни и те же кэшированные значения.

### D5. Значения сетки как источник

`scenarios_envelope` добавляет в `numbers` значения входов сетки: каждое значение каждого входа один раз, подпись `"<имя входа>, значение в сетке"`, единица из индекса. Они идут после минимумов и максимумов выходов и до остальных значений выходов. Иначе `crossing` по сетке `run_scenarios` и фраза ответа «при цене 300» не находят `x` в источниках. Это уточнение ADR-5 «Единый конверт» (MODIFIED). `scenarios_envelope` получает единицы входов через новый аргумент. Тест S1.6 на порядок `numbers` обновляется.

### D6. Каталог и промпт

`READ_TOOLS = [GET_VALUES, DESCRIBE_MODEL]` и `DERIVE` регистрируются в `default_catalog()` с `availability=BASE`, `uses_engine=False`. Поэтому они не попадают в `CalcCache`, лимит расчётов и `engine_gate`. Итого 8 видимых инструментов. Тест считает их по фактической сборке агента. Описания инструментов короткие (контракт §10 п. 1). В системном промпте строка «Ничего не досчитывай сам» дополняется: «разницы, проценты, запас до порога, точку пересечения и эластичность считай через `derive`, передавая числа так, как они указаны в результатах».

### D7. Тесты

- `test_derive.py` — property-based на `hypothesis` (dev-зависимость). Проверяются свойства: `difference(a, b) == −difference(b, a)`; `pct_change(a, a) == 0`; `headroom` меняет знак ровно при переходе через порог; `crossing` лежит в `[x1, x2]` найденного отрезка, и линейная функция в нём даёт `t`; на монотонной сетке `crossing` совпадает с аналитическим корнем прямой; эластичность линейной функции через начало координат равна 1; деление на ноль даёт `invalid_args`, а не исключение. Отдельно идут примерные тесты единиц (`bad_units`, `%`), источников (step_results / выжимка / сообщение пользователя / выдуманный) и допуска округления (`2.81` ↔ `2.8134` принят, `3` ↔ `2.6` отклонён).
- `test_read_tools.py` — `get_values` и `describe_model` на индексе из `FakeContext` и на `index_builder` по `models/Methanex_FinModel.xlsx` (openpyxl, без LibreOffice). Покрываются единицы, типы, `no_values`, `unknown_id`, годы без значений.
- Event loop: при вызове через агент `get_values` / `derive` выполняются не в потоке event loop (проверка `threading.get_ident()` в заглушке `call`).

## Risks / Trade-offs

- **Ложное совпадение операнда.** Небольшое число (например, `1`) может совпасть со случайным источником. Допуск ограничен 0,5 % от источника, а подпись источника видна в `data.operands`. Цель FR-13 — не «вычисление из ничего», и это совпадение её не нарушает: число всё равно взято из результатов.
- **Параллельные вызовы.** Если модель вызовет расчёт и `derive` в одном ответе, `step_results` ещё не будет содержать числа расчёта, и `derive` вернёт `invalid_args`. Промпт уже требует один вызов за раз, а подсказка ошибки ведёт к повтору. Это приемлемо.
- **Числа прошлых ходов теряются.** Выжимка хранит до 16 чисел, остальное отклоняется, и модель получает число заново (`get_values` дешёвый). Чтение `/results/` как источника можно добавить позже.
- **Индекс тяжелее.** Значения выходов: 189 × ~30 лет float на книгу. Это несущественно рядом с кэшем расчётов.
- **Доли и проценты.** Модель может передать `5.1` вместо `0.051`. Это отклоняется явной подсказкой, без молчаливого пересчёта. Если eval S5.1 покажет частые отказы, можно разрешить масштаб ×100 для источников с единицей `%`.

## Migration Plan

Добавление инструментов и полей индекса. v1 не меняется. Откат — убрать регистрацию трёх инструментов из каталога и строку промпта. Новые поля индекса никому не мешают.
