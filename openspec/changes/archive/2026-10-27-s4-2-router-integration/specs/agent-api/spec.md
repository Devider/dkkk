# Spec Delta

## ADDED Requirements

### Requirement: FR-15 Контракт ответа API

`/api/v1/invoke-agent` при `AGENT_ENGINE=v2` SHALL отвечать так же, как v1: ZIP с `txt_response.txt` и `generated/agent_output.xlsx`, состав ZIP MUST NOT меняться; заголовки и тело запроса — без изменений. Трасса хода (план, статусы, сводки результатов) SHALL оставаться на сервере (журнал, Langfuse) и MUST NOT попадать в ответ. Если у пользователя нет загруженного файла, ответ SHALL быть 200 с текстом «загрузите модель». Второй запрос в тот же `thread_id = "{user_id}:{session_id}"`, пока идёт ход, SHALL сразу получать HTTP 409 с просьбой направить вопрос позже, не дожидаясь хода и не меняя состояние сессии. StopEvent GigaChat (HTTP 403 с маркером временной недоступности) при вызове модели агента или смыслового слоя SHALL прерывать ход без повтора и давать HTTP 503.

#### Scenario: ZIP того же состава
- **WHEN** при `AGENT_ENGINE=v2` пользователь с загруженной моделью отправляет вопрос
- **THEN** ответ 200 — ZIP ровно из `txt_response.txt` с текстом ответа и `generated/agent_output.xlsx`

#### Scenario: Нет загруженного файла
- **WHEN** при `AGENT_ENGINE=v2` пользователь без загрузки отправляет вопрос
- **THEN** ответ 200, в `txt_response.txt` — просьба загрузить модель, вызовов LLM нет

#### Scenario: Занятая сессия
- **WHEN** пока идёт ход сессии, приходит второй запрос с тем же `x-user-id` и `x-session-id`
- **THEN** второй запрос сразу получает 409 с просьбой направить вопрос позже, первый завершается обычным ответом, а запрос в другую сессию обрабатывается

#### Scenario: StopEvent GigaChat
- **WHEN** GigaChat отвечает 403 с маркером «temporarily unavailable due to technical reasons» на вызов модели агента или смыслового слоя
- **THEN** ход прерывается без повтора, клиент получает 503 с сообщением о временной недоступности модели; 403 без маркера не превращается в 503

#### Scenario: Интеграционные тесты API
- **WHEN** запускаются `tests/integration/v1_api`
- **THEN** они проходят без правок

## MODIFIED Requirements

### Requirement: FR-20 Переключатель движка агента

Сервис SHALL обслуживать `/api/v1/invoke-agent` агентом v1 или v2 в зависимости от `AGENT_ENGINE` (`v1` по умолчанию). Переключение и откат SHALL выполняться изменением переменной окружения и перезапуском, без пересборки образа. При `AGENT_ENGINE=v1` поведение сервиса SHALL оставаться прежним. Интеграционные тесты API SHALL проходить на обоих значениях `AGENT_ENGINE`.

#### Scenario: По умолчанию работает v1
- **WHEN** `AGENT_ENGINE` не задан
- **THEN** `/invoke-agent` обрабатывает агент v1, как до появления v2

#### Scenario: Включён v2
- **WHEN** `AGENT_ENGINE=v2`
- **THEN** `/invoke-agent` обрабатывает агент v2, и ответ имеет тот же формат: ZIP с `txt_response.txt` и `generated/agent_output.xlsx`

#### Scenario: Откат без пересборки
- **WHEN** после работы на v2 переменная `AGENT_ENGINE` возвращена в `v1` и сервис перезапущен
- **THEN** запросы снова обрабатывает v1 тем же образом

#### Scenario: Неверное значение
- **WHEN** `AGENT_ENGINE` имеет значение, отличное от `v1` и `v2`
- **THEN** сервис не стартует и сообщает допустимые значения

#### Scenario: Интеграционные тесты на обоих движках
- **WHEN** `tests/integration/v1_api` запускаются при `AGENT_ENGINE=v1` и при `AGENT_ENGINE=v2`
- **THEN** оба прогона зелёные
