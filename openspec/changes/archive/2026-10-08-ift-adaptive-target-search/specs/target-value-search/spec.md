# Spec Delta

## Purpose

Подбирает значения входных параметров финансовой модели так, чтобы выбранный выходной показатель
принял заданное целевое значение, и сообщает найденные значения, достигнутый результат и отклонение.

## ADDED Requirements

### Requirement: Определение направления влияния входов

Перед итерациями система SHALL оценить выход модели при исходных значениях всех входов и при
увеличении каждого входа на 10%, чтобы установить знак его влияния на целевой показатель.
Вход с нулевым влиянием SHALL считаться непригодным для коррекции.

#### Scenario: Проба всех входов

- **WHEN** задан список `input_names` из N параметров
- **THEN** система выполняет не менее N+1 вычислений модели до первого итерационного шага и
  хранит знак изменения выхода для каждого входа

#### Scenario: Вход без влияния

- **WHEN** увеличение одного входа на 10% не изменило выход модели
- **THEN** этот вход помечается как нейтральный и не может быть выбран для коррекции

#### Scenario: Вход с нулевым исходным значением

- **WHEN** исходное значение входа равно нулю (10% от нуля — тоже ноль, направление не определить)
- **THEN** вход исключается из поиска, а причина указана в `content.search_configuration`

### Requirement: Критерий выбора входа — штраф и прогноз ошибки

На каждой итерации система SHALL вычислять для каждого пригодного входа комбинированную оценку
`score = normalized_target_error + lambda * penalty` (где `lambda = IFT_SELECTION_LAMBDA = 1`)
и выбирать для коррекции вход с минимальной оценкой. Кандидат SHALL строиться в направлении,
приближающем выход к цели (знак пробы × знак разницы `target_value - current_out`), при этом
на итерацию SHALL приходиться ровно одно реальное вычисление модели.

#### Scenario: Квадратичный штраф по всем пригодным входам

- **WHEN** оценивается коррекция одного из N входов
- **THEN** `penalty = Σ ((x_i - x_i^0) / base_step_i)^2` по всем пригодным входам, где
  `base_step_i = 0.1 * |x_i^0|` считается один раз при старте; исключённые (нулевые и
  нейтральные) вносят нулевой вклад

#### Scenario: Распределённое изменение дешевле концентрированного

- **WHEN** сравниваются гипотетические точки «+base_step на трёх входах» и «+3·base_step на одном»
- **THEN** их штрафы равны 3 и 9 соответственно, поэтому распределённое изменение набирает меньшую оценку

#### Scenario: Прогноз ошибки не требует дополнительных вычислений модели

- **WHEN** строится кандидат для входа `i` с шагом `f_i * base_step_i`
- **THEN** `normalized_target_error = ||current_out - target_value| - sens_i * f_i| / N`, где
  `sens_i` — дельта выхода из пробы, `N = max(|baseline_out - target_value|, e)` — начальное
  расстояние до цели, а модель вызывается один раз для выбранного кандидата

#### Scenario: Накопленное отклонение перенаправляет поиск

- **WHEN** один вход уже сдвинут на несколько базовых шагов, а другой ещё нет
- **THEN** квадратичный штраф делает следующий шаг по сдвинутому входу дороже, поэтому коррекция
  распределяется между входами, если выигрыш по чувствительности не компенсирует рост штрафа

### Requirement: Адаптивный размер шага

`base_step_i = 0.1 * |x_i^0|` SHALL вычисляться один раз при старте от исходного значения входа и
SHALL не пересчитываться от текущих значений. Фактический шаг входа SHALL равняться доле
`f_i * base_step_i`, где доля стартует с 1 и после промаха (увеличения `|value - target_value|`
относительно текущей точки) делится пополам: 1, 0.5, 0.25, ...; доля обратно не растёт.

#### Scenario: Начальный шаг

- **WHEN** выполняется первая коррекция входа
- **THEN** значение входа изменяется на `base_step_i`, что составляет 10% от его исходного значения

#### Scenario: Промах уменьшает шаг

- **WHEN** коррекция увеличила отклонение от целевого значения
- **THEN** следующая коррекция того же входа выполняется с шагом `f_i * base_step_i`, где доля
  уменьшена вдвое, а `base_step_i` по-прежнему равен 10% от исходного значения входа

### Requirement: Критерий останова

Система SHALL останавливать поиск при `|value - target_value| < e` либо при достижении количества
итераций `MAX_ITER`; в результате SHALL указываться, какое условие сработало и какое лучшее
значение найдено.

#### Scenario: Попадание в допуск

- **WHEN** отклонение стало меньше `e`
- **THEN** поиск прекращается, статус — `OK`, в результате передаются значения входов и достигнутый выход

#### Scenario: Исчерпание итераций

- **WHEN** выполнено `MAX_ITER` итераций при отклонении ≥ `e`
- **THEN** поиск прекращается, статус — `WARNING`, в результате передаются лучшая найденная точка,
  её отклонение и признак того, что допуск не достигнут

### Requirement: Отсутствие жёстких границ значений входов

Система SHALL не ограничивать значения входов жёстким диапазоном (например ±50% от исходных);
штраф SHALL использоваться только как критерий выбора, а не как фильтр допустимых точек.

#### Scenario: Цель за пределами старой сетки

- **WHEN** целевое значение достижимо только при значениях входов дальше ±50% от исходных
- **THEN** поиск возвращает эти значения со статусом `OK`, если отклонение меньше `e`

### Requirement: Совместимость результата с потребителями инструмента

Система SHALL сохранять контракт инструмента: сигнатуру `analyze_model_inputs_for_target`,
статусы `OK`/`WARNING`/`ERROR` и содержательные ключи `content`
(`target_value`, `tolerance_percent`, `input_names`, `current_input_values`,
`matching_scenarios`, `all_scenarios`, `processing_time_seconds`), чтобы ответы агента и
лог-парсеры продолжали работать.

#### Scenario: Успешный подбор

- **WHEN** допуск достигнут
- **THEN** `content.matching_scenarios` содержит хотя бы один сценарий с `input_values`,
  `output_value`, `deviation`, `deviation_percent`

#### Scenario: Ошибка входных данных

- **WHEN** `input_names` пуст или файл модели не найден
- **THEN** возвращается статус `ERROR` с объясняющим сообщением, как и до изменения

### Requirement: Кэширование по всем параметрам поиска

Ключ кэша результатов SHALL включать все параметры, влияющие на ход поиска (целевая переменная,
допуск, список входов, размер шага, `MAX_ITER`, `lambda`, `e`, пользователь), так что изменение любого
из них SHALL приводить к новому расчёту, а повтор идентичного запроса — к ответу из кэша.

#### Scenario: Повтор идентичного запроса

- **WHEN** приходит запрос с теми же аргументами, что и ранее рассчитанный
- **THEN** ответ возвращается без новых вычислений модели

#### Scenario: Изменение настроек поиска

- **WHEN** меняется `MAX_ITER`, размер шага или `lambda` при прочих равных
- **THEN** результат не берётся из кэша и поиск выполняется заново
