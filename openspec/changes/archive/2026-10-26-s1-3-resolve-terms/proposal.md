Story S1.3 · FR-6 · ADR-4 · решения spike S0.3 (`archive/2026-10-26-s0-3-skills-resolve-spike/design.md`) · §9 `resolved_terms` · §10 каталог

## Why

Промах сопоставления имён — главный источник ошибок v1 (~55 % точности на параметр), и в v1 он спрятан внутри расчётного инструмента: модель его не видит и не может исправить. ADR-4 выносит сопоставление в отдельный инструмент `resolve_terms`: модель получает кандидатов и уровень уверенности до расчёта и при низкой уверенности сверяет по смыслу, переформулирует или спрашивает. Расчётные инструменты (S1.1, S1.2) уже принимают только ID индекса — не хватает инструмента, который эти ID выдаёт.

## What Changes

- Инструмент `resolve_terms` (базовый, без движка): вход — термины `[{text, role: input | output}]`; выход — по каждому термину кандидаты `{id, name, score}` и `confidence: high | low` либо `term_not_found`.
- Кандидаты — по решению S0.3: первым выбор неизменённого `AnalyzerSubAgent` (EMA-анализатор на сообщении со списком терминов), затем Jaccard top-2 других имён индекса; `score` — Jaccard-сходство (справочно); `confidence = high`, если выбор анализатора входит в Jaccard top-3 термина, иначе `low`.
- Устойчивость: падение анализатора на пустом ID (`KeyError`, дефект v1) → повтор по одному термину; 429 GigaChat → повтор с паузой; термин без кандидатов → `term_not_found` в результате этого термина.
- Результат записывается в состояние агента: поле `resolved_terms` (термин → `{id, name, confidence}`) через `Command`; адаптер учится обновлять состояние и вызывать асинхронные доменные функции.
- Скрипт оценки точности на эталоне Methanex (выборка S0.3) против базовой линии v1.

**Вне рамок:** `ambiguous_term` (критерий неоднозначности не определён — после eval S5.1); использование `resolved_terms` в следующих ходах (S2.6); сброс при смене файла (S2.2); гибридный поиск без LLM (после v2, ADR-4).

## Impact

- Новые `api/v2/tools/resolve_terms.py`, `api/v2/tools/state.py`; правка `adapter.py` (асинхронный вызов, обновление состояния), `catalog.py` (регистрация).
- Смысловой слой (`AnalyzerSubAgent`, промпты, схемы, Jaccard) не меняется; v2 импортирует его модули напрямую, без `main_graph`.
- Каждый вызов `resolve_terms` — 1–2 вызова GigaChat (анализатор, `lookup_more`), при падении — до N+1.
- Скрипт `scripts/eval/resolve_terms_accuracy.py` (живой GigaChat, не pytest).
