# Design

## Context

Мотивация — proposal.md, требования — `specs/agent-tools/spec.md`.

Что даёт книга (`subagents/utils.py:build_mappings`, openpyxl, без LibreOffice): входы — `row_mapping[norm] = {original, row, values: {год: значение}}` и общие `year_columns` (Methanex: 2001–2050); выходы — `output_mapping[norm] = {original, values: {год: значение}}` (Methanex: с 2018); у заголовков разделов `values` пуст. Проверено при реализации: в Methanex пусто у 128 из 189 выходов — это строки без значений по годам (формула в строке есть только у ячейки единиц `=$G$2`), в том числе необязательные «заполняется при наличии информации»; v1 на них даёт `returned None`, поэтому `no_values` до движка корректен. ID индекса (`IN<n>`, `OUT<n>`) — порядковый номер строки в этих словарях (`_build_catalog_with_ids`).

Состояние после S1.3: `ModelIndex` хранит только `ID → имя`; схемы расчётных инструментов требуют все поля, поэтому пропущенный год даёт ошибку валидации в `ToolNode` (не конверт); проверки аргументов — внутри домена, после запуска `soffice`; IFT без найденных сценариев — успех с оговоркой (S1.2), но без `reachable`.

## Goals / Non-Goals

**Goals:**
- Любое нарушение §10 п. 2 ловится до движка и приходит модели с кодом.
- FR-10 на уровне инструмента: отсутствие данных — `missing_input`, а не догадка.

**Non-Goals:**
- `blocked` и продолжение плана — S2.6.
- Проверка единиц для `find_input_for_target`: модель не задаёт там диапазоны (их строит домен).

## Decisions

### D1. Индекс с годами и значениями

`ModelIndex` получает два необязательных поля (по умолчанию пусто — тогда проверки, зависящие от них, пропускаются): `input_values: {ID: {год: значение}}`, `output_years: {ID: (годы со значением)}`. Новый `index_builder.build_model_index(path) -> ModelIndex` строит всё за один проход `build_mappings` в том же порядке, что `_build_catalog_with_ids` (тест сверяет ID). Синхронный — вызывается при загрузке файла / в `TurnContext` через `to_thread` (S2.2).

### D2. Необязательные поля и `missing_input`

В схемах `year`, `target`, `min`, `max`, `step` — `Optional` с `None` по умолчанию, описание говорит «не придумывай, если пользователь не назвал». Проверка собирает все недостающие разом: «Не указаны: год; диапазон для «Метанол»». Пустые списки `inputs` / `outputs` / `input_ids` — тоже `missing_input`.

*Альтернатива:* обязательные поля — отвергнута: модель додумывает значение, чтобы пройти схему, а ошибка схемы `ToolNode` не несёт кода.

### D3. Порядок проверок

`missing_input` → `unknown_id` → `no_values` (выход без лет) → год вне `output_years` (`invalid_args`, «доступны 2018–2050») → диапазоны: `min > max` или `step ≤ 0` (`invalid_args`) → размер сетки → `bad_units` → (IFT) `tolerance ≤ 0` (`invalid_args`). Первая найденная категория возвращается со всеми нарушениями этой категории.

Сетка из одной точки (`min == max`) разрешена: так `scenario-analysis` закрывает точечный «что если» в первой волне (§11, решённый открытый вопрос). Это уточняет §10 п. 2 («`min < max`») — фиксируется в документе спецификации.

### D4. Размер сетки

`points(i) = floor((max − min) / step + 1e-9) + 1`, размер — произведение по входам; лимит — `APP_CONFIG.agent.max_grid` (`AGENT_MAX_GRID`, 400). Домен сам режет на `MAX_SCENARIOS` = 100 000 после запуска — наш лимит строже и срабатывает до движка.

### D5. `bad_units`

База `b` — значение входа в запрошенном году, иначе в ближайшем году с значением; нет значений — проверка пропускается. `m = max(|min|, |max|)`.
- доля против процентов: `|b| ≤ 1` и `m ≥ 2` и `m ≥ 20 · max(|b|, 0,01)`;
- проценты против доли: `|b| ≥ 2` и `|b| ≥ 20 · max(m, 0,01)` (уточнено при реализации: условие `m ≤ 1` убрано — оно не пропускало пример ниже, курс 95 с диапазоном 0,9–1,1).

Порог 20× даёт запас: коэффициент 1,0 с диапазоном 0,8–1,2 и цена 400 с диапазоном 300–500 не срабатывают; инфляция 0,05 с диапазоном 5–10 и курс 95 с диапазоном 0,9–1,1 — срабатывают. В `error` — «Базовое значение «X» в 2026: 0,05; диапазон 5–10», в `hint` — «пересчитай диапазон в тех же единицах, что и база».

### D6. `reachable`

`target_envelope` (S1.2) пишет `data.reachable = not unreached`; ближайшая точка при `false` уже есть (S1.2). Это закрывает FR-11.

## Risks / Trade-offs

- [Эвристика `bad_units` ошибается на входах с базой около 1 и широким осмысленным диапазоном (например, индекс 1,0 → 0–3)] → порог 20× и требование `m ≥ 2`; подсказка показывает базу, модель может повторить с тем же диапазоном, если он верен, — при повторе с теми же аргументами проверка снова сработает, поэтому в `hint` прямо сказано, что диапазон в тех же единицах проходит. Доля ложных срабатываний — метрика в eval S5.1.
- [Индекс без лет и значений (старый путь)] → проверки, зависящие от них, пропускаются; тест на это.
- [`AGENT_MAX_GRID` = 400 может быть мало для 3 входов] → 7 × 7 × 7 = 343 проходит; значение настраивается.
