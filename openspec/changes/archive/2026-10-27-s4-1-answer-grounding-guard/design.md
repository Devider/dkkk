# Design

## Context

Мотивация — в proposal.md, требование — в `specs/agent-answer/spec.md`. Основа: ADR-9, §8 правило 7 и стек №18–19, §13 риск ложных срабатываний, spike S0.2 (C7: последним сообщением промпта не может быть ответ модели).

Что уже есть в коде:
- `tools/grounding.py` (S1.7): `Source(value, label, unit)`, `collect_sources(state)` (`step_results[*].numbers`, `turn_summaries[*].results[*].numbers`, числа всех `HumanMessage`), `numbers_in_text`, `tolerance(value, source)` (половина последнего разряда из `repr(float)`, не больше 0,5 % источника), `match`. Всё это использует `derive`, и его поведение менять нельзя.
- `PlanCompletionGuard` (S2.4) стоит последним перед `TurnSummary`, `after_model` с `can_jump_to=["model"]`. Ответ при открытых шагах получает напоминание `HumanMessage` и `jump_to="model"`. Принятый ответ заменяется `AIMessage` с тем же `id` и разделом «Не выполнено».
- В `langchain.agents.factory` хуки `after_model` связаны цепочкой снизу вверх. `jump_to` из одного хука уходит прямо в цикл модели, остальные `after_model` этого прохода не выполняются.
- `guard_counters` обнуляет `TurnContext` в начале хода. `limits.limit_hit(state)` и `limits.turn_timeout(state)` говорят, что ход исчерпан.
- `answer_check.py` (S3.2): детерминированные проверки ответа для тестов и eval, `SECTIONS`, `_sections(text)`.
- Для единицы «доля» `get_values` отдаёт доли (`0.05` = 5 %). Модель пишет такие значения процентами.

## Goals / Non-Goals

**Goals:**
- Ответ с выдуманным числом один раз возвращается модели, затем число снимается с оговоркой (критерий S4.1).
- Мало ложных срабатываний на годах, номерах, счёте, округлении, процентах-долях и знаке.
- Один детектор для guard и eval.

**Non-Goals:**
- Eval-прогон и метрики на GigaChat (S5.1), пересчёт масштабов и единиц, пороги из skill (S3.4), ответы v1.

## Decisions

### D1. Место в стеке и поток

`AgentFactory.middleware()`: `AnswerGroundingGuard(settings.grounding_max_returns)` ставится после `*self.extra_middleware` и перед `*guard` (`PlanCompletionGuard`), как в таблице §8 (№18 над №19). Guard ставится всегда, в том числе при `AGENT_PLAN_MODE=off`.

Поток `after_model` снизу вверх:
1. `PlanCompletionGuard` при открытых шагах делает `jump_to="model"`, и guard чисел этот ответ не видит. Принятый ответ (возможно, с «Не выполнено») идёт дальше.
2. `AnswerGroundingGuard` проверяет последний `AIMessage` без `tool_calls`. Ответ с вызовами инструментов и ход без `AIMessage` пропускаются.

Фиксированные ответы без LLM (`TurnContext`, `LanguageGuard`) до `after_model` не доходят. Текст `LIMIT_FALLBACK` / `TIMEOUT_FALLBACK` чисел не содержит.

### D2. Числа ответа: разбор и исключения (`tools/grounding.py`)

Новая функция `answer_numbers(text) -> list[Mention]`, где `Mention(start, end, written, value, decimals, percent)`. Она использует то же регулярное выражение `_NUMBER` через `finditer`, чтобы знать позиции и число знаков после запятой ровно так, как написано («2,50» → 2 знака). Не проверяются (spec, правила сравнения):
- **год:** целое 1900–2100 без разделителей тысяч, дробной части и `%`;
- **номер пункта:** число в начале строки (после отступа и `|`/`-`/`*` не считается) с `.` или `)` и пробелом: `^\s*\d+[.)]\s`;
- **обозначение:** перед числом буква, цифра-буква или `_`, либо после числа буква, кроме множителя `x`/`х` (`P143`, `Q4`, `CO2`, `S1`, `FY2025`);
- **дата:** `\d{1,2}\.\d{1,2}\.\d{2,4}` — все числа внутри;
- **малое целое:** 0–10 без дробной части и без `%`.

`numbers_in_text` (источники из сообщений пользователя) не меняется: в источниках лишнее число ложного подтверждения почти не даёт, а пропущенное дало бы ложное срабатывание.

*Отклонение от FR-13 («каждое число»):* малые целые не проверяются. Причина: в ответах это почти всегда счёт («за 3 года», «в 2 сценариях»), а снятие давало бы «за н/д года». Решение подтвердил пользователь 2026-10-27. Цена: выдуманное значение 0–10 без единиц пройдёт, поэтому eval S5.1 смотрит на такие случаи отдельно.

### D3. Сравнение (`tools/grounding.py`)

Новая функция `confirm(mention, sources) -> Source | None`. Допуск: `min(0.5 · 10^(−decimals), 0.005 · |s|)`, где `decimals` берётся из записи в ответе, а не из `repr(float)`. Кандидаты:
- `| |v| − |s| | ≤ допуск`, где знак не учитывается;
- при `percent` дополнительно `| |v| − |s|·100 | ≤ min(0.5 · 10^(−decimals), 0.005 · |s|·100)`, то есть доля 0.125 ↔ 12,5 %.

`tolerance` и `match` для `derive` не меняются (регресс-тест в `test_derive.py`). Масштабы (тыс., млн, млрд) не пересчитываются (risks).

*Альтернатива:* расширить `match` флагами — отвергнута. У `derive` знак значим (операнд −30 и 30 дают разные запасы), и смешивать правила в одной функции опасно.

### D4. Детектор для eval (`answer_check.py`)

`unconfirmed_numbers(text, sources) -> list[Mention]` проходит по `answer_numbers` и оставляет те, для которых `confirm` вернул `None`. Eval S5.1 вызывает его с `collect_sources(state)` хода. Guard использует ту же функцию, поэтому правила у них одни.

### D5. Возврат модели (`middleware/grounding.py`)

`AnswerGroundingGuard(max_returns)`, `state_schema` с `guard_counters`, `after_model` / `aafter_model` с `@hook_config(can_jump_to=["model"])`:
1. Последнее сообщение — `AIMessage` без `tool_calls`, иначе `None`.
2. `unconfirmed = unconfirmed_numbers(answer.text, collect_sources(state))`. Если список пуст, возвращается `None` и ответ не меняется.
3. Если `grounding_returns < max_returns` и не `limit_hit(state)`, возвращается `{"messages": [HumanMessage(GROUNDING_REMINDER.format(numbers=...))], "guard_counters": {..., "grounding_returns": n + 1}, "jump_to": "model"}`. В списке чисел — уникальные записи в порядке появления, как они написаны в ответе. Ранний ответ остаётся в истории, как в S2.4 D3.
4. Иначе ответ снимается (D6), и `guard_counters.grounding_removed` = число снятых вхождений.

`limit_hit` покрывает и таймаут: `Cancellation` выставляет `LIMIT_HIT` вместе с `TURN_TIMEOUT` (S2.8).

*Найдено при реализации:* `collect_sources` считал источником любой `HumanMessage`. Поэтому напоминание guard со списком чисел «подтверждало» эти же числа при втором ответе, и снятие никогда не срабатывало. То же касалось напоминания `PlanCompletionGuard` и текста закреплённого skill (`lc_source="pinned_skill"`). Решение: служебные сообщения в роли пользователя создаются через `grounding.agent_note(text)` с меткой `additional_kwargs["lc_source"] = "agent_guard"`, и `collect_sources` пропускает любой `HumanMessage` с `lc_source`. Это касается и `derive`: его операнды тоже больше не подтверждаются текстом напоминаний и skill (пороги из skill — S3.4).

Напоминание (`prompts/middleware.py`, на русском): «В ответе есть числа, которых нет в результатах инструментов и в сообщениях пользователя: {numbers}. Получи каждое инструментом (разницу, процент изменения, запас до порога — через `derive`) или убери его из ответа. Затем дай финальный ответ заново.» После возврата модель может вызвать инструменты. Следующий ответ без вызовов снова проходит оба guard, и при исчерпанном счётчике числа снимаются.

### D6. Снятие числа с оговоркой

- Вхождения заменяются справа налево по `(start, end)`: число, а при `percent` и знак `%` с пробелом перед ним, превращаются в `н/д`. Знак минуса входит в `_NUMBER` и снимается вместе с числом.
- Оговорка `GROUNDING_CAVEAT = "Часть чисел убрана из ответа: они не подтверждены результатами расчёта."`:
  - если в аналитическом ответе есть раздел «Оговорки», строка `- {caveat}` дописывается в конец его тела (перед следующим известным разделом или в конец текста);
  - если раздела нет, в конец добавляется `## Оговорки` и строка (по шаблону skill `economic-answer`);
  - в ответе без разделов (`not is_analytic`) — последний абзац.
- Итог — `AIMessage(text, id=answer.id)`, который заменяет ответ в `messages`, как в `PlanCompletionGuard`. Для этого `answer_check._sections` становится публичной `sections` (старое имя остаётся у внутренних вызовов через замену, поведение то же).

### D7. Журнал

`logger.info("AnswerGroundingGuard: {} unconfirmed, action={}", n, "return" | "removed")` через позиционные аргументы loguru (CLAUDE.md: никаких f-строк с текстом ответа). Сами числа в журнал не пишутся: это часть ответа пользователю, достаточно счётчика. Счётчики `grounding_returns` / `grounding_removed` в `guard_counters` — основа метрики «доля срабатываний» для S5.1.

### D8. Настройка

`AgentSettings.grounding_max_returns: int = Field(default=1, ge=0, validation_alias="AGENT_GROUNDING_MAX_RETURNS")`, строка в таблице параметров README рядом с `AGENT_PLAN_MAX_RETURNS`.

## Risks / Trade-offs

- [Масштаб: модель пишет «1,2 млрд» по источнику 1 200 млн] → число снимается. Skill требует единицы как в результате. Доля таких снятий видна по `grounding_removed` в eval S5.1; пересчёт масштабов — отдельная story при необходимости.
- [Модель округляет сильнее, чем в результате (1 234 → «1 200»)] → допуск по записанным знакам это не пропускает, будет возврат, затем снятие. Это намеренно и совпадает с `derive` и skill («не округляй сильнее, чем в результате»).
- [Малые целые и годы без проверки] → пропуск выдуманного значения 0–10 или года как значения. Eval смотрит на эти случаи.
- [Лишний вызов модели на ход при срабатывании] → максимум 1 по умолчанию, учитывается `ModelCallLimit` (FR-9).
- [Число из `/results/`, которого нет в `step_results`] → `step_results` хранят полные `numbers` (S1.6), так что расхождение возможно только для чисел вне `numbers`. Тогда число снимается.
- [Числа в разделе «Не выполнено» из текста шагов плана] → проверяются как остальные. Шаги обычно повторяют числа пользователя, и они подтверждаются.

## Migration Plan

Только v2. Выключить возврат без изменения кода можно через `AGENT_GROUNDING_MAX_RETURNS=0`: снятие с оговоркой остаётся. Полного выключения guard конфигурацией нет: FR-13 обязателен (ADR-9).
