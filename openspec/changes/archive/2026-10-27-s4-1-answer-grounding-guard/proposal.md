Story S4.1 · FR-13 (владелец) · ADR-9 · AR-Q5 (новая переменная в README, требование не меняется) · §8 правило 7, стек №18 · §13 риск «`AnswerGroundingGuard` ложно срабатывает»

## Why

Spike S0.2 показал, что GigaChat сам досчитывает производные числа и иногда пишет числа, которых нет ни в одном результате. `derive` (S1.7) даёт модели честный способ считать производные, а skill `economic-answer` (S3.2) и системный промпт запрещают выдумывать числа. Но финальный ответ пока никто не проверяет. По ADR-9 перед отдачей ответ проверяет `AnswerGroundingGuard`, а без него FR-13 не выполняется. `grounding.py` (S1.7) уже собирает источники чисел и сравнивает числа с допуском на округление, поэтому guard использует его без своей логики поиска.

## What Changes

- **`AnswerGroundingGuard` — новый middleware (`after_model`, §8 №18).** Он проверяет финальный ответ: `AIMessage` без вызовов инструментов, уже принятый `PlanCompletionGuard`. Каждое число ответа ищется в источниках FR-13 через `grounding.collect_sources` / `match`: `numbers` результатов этого хода, числа выжимок прошлых ходов и числа из сообщений пользователя.
- **Одна перегенерация.** Если в ответе есть неподтверждённые числа, модель получает отдельным сообщением пользователя (spike S0.2 C7) их список и указание: получить число инструментом (производные — через `derive`) или убрать его. Затем ход возвращается модели (`jump_to="model"`). Число перегенераций за ход задаёт настройка, по умолчанию 1. Если исчерпан лимит хода или истекло время (FR-9, AR-Q10), перегенерации нет.
- **Снятие числа с оговоркой.** Если неподтверждённые числа остались после перегенерации, каждое из них (вместе со знаком `%`) заменяется на «н/д». В раздел «Оговорки» добавляется строка о том, что неподтверждённые числа убраны. Если раздела нет, он создаётся, а в ответе без разделов строка ставится в конец. Сами убранные числа в оговорку не попадают.
- **Какие числа проверяются (§13, риск ложных срабатываний).** Не проверяются годы, номера пунктов списка, числа внутри обозначений (`P143`, `Q4`, `CO2`), даты и малые целые 0–10 без `%` и без дробной части («за 3 года»). Число сравнивается по модулю, потому что знак часто передан словом («снизится на 12»). Число с `%` подтверждается также долей (`5 %` ↔ `0.05` с единицей «доля»). Допуск на округление считается по тому, сколько знаков написано в ответе.
- **Детектор для eval.** Чистая функция `unconfirmed_numbers(text, sources)` без LLM лежит рядом с `answer_check`, её используют guard и eval (S5.1).
- **Наблюдаемость.** В `guard_counters` пишутся `grounding_returns` и `grounding_removed`, срабатывание guard пишется в журнал (без самих чисел ответа в тексте исключений). Это даёт метрику «доля срабатываний» для eval.
- **Настройка (AR-Q5).** `AGENT_GROUNDING_MAX_RETURNS` (по умолчанию 1, ≥ 0; 0 — сразу снятие).

**Вне рамок:** eval-прогон и метрика «100 % чисел подтверждены» на GigaChat (S5.1). Пересчёт масштабов (млн ↔ млрд, тыс.) и единиц: число в другом масштабе считается неподтверждённым. Пороги из текста skill как источник (S3.4). Числа из файлов `/results/`, которых нет в `step_results`. Проверка ответов v1. Отдельная проверка частичного ответа при лимите: он проверяется теми же правилами, но без перегенерации.

## Impact

- Новый модуль: `api/v2/middleware/grounding.py` (`AnswerGroundingGuard`).
- Изменения: `api/v2/tools/grounding.py` (разбор чисел ответа с позициями и числом знаков, исключения, сравнение по модулю и доле, допуск по записанным знакам; поведение `match` для `derive` не меняется), `api/v2/answer_check.py` (`unconfirmed_numbers`), `api/v2/prompts/middleware.py` (напоминание и оговорка на русском), `api/v2/factory.py` (guard перед `PlanCompletionGuard`; ставится и в режиме `off`), `config/agent/config.py` (`grounding_max_returns`).
- Тесты: новый `tests/unit/v2/test_grounding_guard.py`; дополняются `test_derive.py` (регресс `match`), `test_runtime.py` (порядок стека).
- Поведение v1 и контракт HTTP API не меняются.
