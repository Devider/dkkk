## ADDED Requirements

### Requirement: AR-Q6 Вынос результата длиннее порога

Если сериализованный конверт успешного результата инструмента длиннее порога `AGENT_RESULT_MAX_CHARS` (символы JSON, по умолчанию 1500), полный конверт SHALL сохраняться в хранилище результатов по пути `/results/<ход>/<вызов>.json`, а модель SHALL получать компактный конверт: `status`, `result`, `notes`, `hint`, `numbers` и `ref` — путь к полному результату. Структурированные данные `data` MUST NOT попадать в компактный конверт. Ни один результат доменного инструмента (все, кроме `read_file` и `write_todos`, которые результатов расчёта не возвращают) в сообщениях модели MUST NOT быть длиннее порога: если компактный конверт не помещается, урезается список `numbers` с конца, затем сводка `result`; урезание отмечается в `notes`. Числа сценарной сетки SHALL идти по важности: сначала минимум и максимум каждого выхода, затем остальные. Полный результат SHALL читаться инструментом `read_file` по `ref`, по частям через `offset` и `limit`. Результат не длиннее порога и конверт ошибки SHALL отдаваться без выноса и без `ref`. Для каждого вызова доменного инструмента, который дошёл до инструмента и вернул конверт (в том числе из кэша сессии), в состоянии хода SHALL сохраняться запись с инструментом, статусом, кодом ошибки, сводкой, `ref` и полным списком `numbers`.

#### Scenario: Большая сценарная сетка
- **WHEN** `run_scenarios` возвращает сетку, конверт которой длиннее порога
- **THEN** в сообщении модели не больше `AGENT_RESULT_MAX_CHARS` символов: сводка, минимум и максимум каждого выхода в `numbers` и `ref`, без таблицы `data`

#### Scenario: Полный результат по ссылке
- **WHEN** модель вызывает `read_file` с путём из `ref`
- **THEN** она получает полный конверт результата, включая `data` и все `numbers`, и может дочитать длинный файл через `offset`

#### Scenario: Короткий результат не выносится
- **WHEN** конверт результата не длиннее порога
- **THEN** модель получает его целиком, `ref` нет, в хранилище результатов ничего не пишется

#### Scenario: Ошибка не выносится
- **WHEN** инструмент возвращает конверт ошибки
- **THEN** модель получает `{error, code, hint}` целиком, без `ref`

#### Scenario: Компактный конверт не помещается
- **WHEN** сводка и все числа результата вместе длиннее порога
- **THEN** в сообщение попадает начало списка `numbers`, в `notes` — пометка, что полный список в `ref`, а сообщение не длиннее порога

#### Scenario: Полные числа хода в состоянии
- **WHEN** результат вынесен и модель видит только часть `numbers`
- **THEN** запись этого вызова в состоянии хода содержит полный список `numbers` и `ref`

#### Scenario: Повтор из кэша
- **WHEN** расчёт с вынесенным результатом повторяется и отдаётся из кэша сессии
- **THEN** модель получает тот же компактный конверт с тем же `ref`, по которому читается полный результат, а запись вызова попадает в состояние текущего хода

### Requirement: AR-Q7 Изоляция вынесенных результатов

Хранилище вынесенных результатов SHALL разделяться по пользователю: пространство записи и чтения SHALL определяться `user_id` из контекста запроса, а не путём из аргументов модели. Пользователь MUST NOT читать результат другого пользователя ни по точному `ref`, ни при том же `x-session-id`, ни через относительные сегменты пути.

#### Scenario: Свой результат читается
- **WHEN** модель в ходе пользователя A читает `ref`, полученный в ходе того же пользователя
- **THEN** `read_file` возвращает полный результат

#### Scenario: Чужой результат не читается
- **WHEN** в ходе пользователя B с тем же `x-session-id` модель читает `ref` из результата пользователя A
- **THEN** `read_file` отвечает, что файл не найден, и содержимое результата A в ответ не попадает

#### Scenario: Путь не выбирает пространство
- **WHEN** модель передаёт в `read_file` путь `/results/` с сегментами `..` или с чужим `user_id` в пути
- **THEN** чтение идёт только в пространстве текущего пользователя, и чужой результат не находится
