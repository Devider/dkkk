# Design

## Context

Мотивация — proposal.md, требования — `specs/agent-answer/spec.md`. ADR-9, §11 (`economic-answer`, «Активация» п. 2), §14, spike S0.2 (ADR-9: структуру FR-12 даёт агент сам, 6/6), spike S0.3 (закрепление).

Состояние:
- `SkillsMiddleware` (deepagents 0.7.29) закрепляет skills из ключа состояния `pinned_skills` в `before_model`: тело `SKILL.md` без фронтматтера добавляется отдельным `HumanMessage` с `additional_kwargs={"lc_source": "pinned_skill", "skill": {name, path, description}}`, ключ очищается. Неизвестное имя молча пропускается. Каждое закрепление — новая копия (S0.3: копии копятся, если закреплять каждый ход).
- `TurnContext.before_agent` (S2.2) уже обновляет состояние хода; `SkillsMiddleware.before_agent` загружает `skills_metadata` после него, закрепление срабатывает в `before_model` — к этому моменту метаданные есть.
- Сообщение закрепления встаёт после вопроса пользователя (первый ход сессии). `turn_message_id` (S2.6) указывает на вопрос — граница хода не сдвигается.
- `PlanCompletionGuard` (S2.4) выбирает язык раздела «Не выполнено» по последнему `HumanMessage`; для английского вопроса пишет «Not done» — расходится с FR-14.
- Системный промпт (S2.1) уже требует делового русского и запрещает ID, коды и имена инструментов.
- ID индекса — `IN<n>` / `OUT<n>` (`index_builder`); коды ошибок — `ErrorCode`.

## Goals / Non-Goals

**Goals:**
- Структура FR-12 задаётся skill, а не кодом; skill всегда в контексте, без копий.
- Детерминированная проверка ответа, общая для тестов и eval.
- Замер на GigaChat до S5.1.

**Non-Goals:**
- Подтверждение чисел (S4.1), `derive` (S1.7), конфигурация закрепления (S3.5).

## Decisions

### D1. Skill `economic-answer`

Тело (≤ 300 строк, проверяется `validate_skills`):
- Когда применять разделы: ход с расчётом или выводом по результатам модели. Без разделов: вопрос о недостающем (одна-две фразы и вопрос), отказ, приветствие, пояснение без цифр.
- Разделы — заголовки `## Вывод`, `## Ключевые цифры`, `## Анализ`, `## Где в модели`, `## Оговорки`, в этом порядке; пустой раздел опускается.
  - Вывод — 1–3 предложения, ответ на вопрос и смысл для кредитора; недостижимая цель — «Недостижимо: максимум … при …» (FR-11).
  - Ключевые цифры — таблица Markdown: показатель, год, значение, единицы; числа только из результатов инструментов.
  - Анализ — чувствительность, запас прочности, драйверы; без досчёта (производные числа — только из результатов).
  - Где в модели — названия показателей модели (не ID) и листы, если известны.
  - Оговорки — допущения (абсолютный диапазон из относительного, выбранный кандидат при низкой уверенности), пропущенные и ждущие ответа шаги с причиной.
- Стиль: деловой русский, без вводных и повторов вопроса, без служебных слов (инструменты, коды, ID, статусы плана).
- Пример ответа на сценарный запрос (на условных числах с пометкой, что числа — пример).

`metadata.include_tools` нет: `derive` появится в S1.7.

### D2. Закрепление

`AgentFactory(..., pinned_skills=DEFAULT_PINNED)`, `DEFAULT_PINNED = ("economic-answer",)`; передаётся в `TurnContext(pinned_skills=...)`. `build()`: после `validate_skills` — каждое закреплённое имя должно быть среди найденных skills, иначе `SkillsError("закреплённый skill <name> не найден")`.

`TurnContext._turn_update`: `pinned_skills = [n for n in pinned if not _pinned_in(messages, n)]`, где `_pinned_in` ищет `HumanMessage` с `additional_kwargs.lc_source == "pinned_skill"` и `skill.name == n`; ключ пишется, только если список не пуст. Сброс при смене книги не нужен: skill не зависит от модели. После сжатия истории (S2.7), если сообщение закрепления удалено, skill закрепится снова.

Ключ `pinned_skills` объявлен в состоянии `SkillsMiddleware`; `TurnContext` пишет его в объединённое состояние графа.

### D3. Только русский в `PlanCompletionGuard`

Убираются `_TEXTS["en"]` и `_language`: напоминание и раздел «Не выполнено» всегда на русском (FR-14). Заодно исчезает зависимость от «последнего `HumanMessage`», которым теперь может быть сообщение закрепления. Раздел «Не выполнено» guard пишет как `## Оговорки`-совместимый текст: `**Не выполнено:**` + список — формат S2.4 сохраняется.

### D4. Проверка ответа (`api/v2/answer_check.py`)

```python
SECTIONS = ("Вывод", "Ключевые цифры", "Анализ", "Где в модели", "Оговорки")
def structure_issues(text) -> list[str]   # FR-12, для аналитического ответа
def hygiene_issues(text) -> list[str]     # FR-14, для любого ответа
def is_analytic(text) -> bool             # есть хоть один заголовок раздела
```
- Разделы — строки-заголовки `#`…`###` или `**…**` с названием раздела (регистр и двоеточие не важны); вне перечня заголовки допустимы.
- Структура: есть «Вывод», и он первый из разделов; порядок разделов по `SECTIONS`; нет повторов; «Вывод» — 1–3 предложения (разбиение по `.!?` с учётом десятичных чисел); «Ключевые цифры» содержит таблицу (строка `|…|` и разделитель `|---|`); раздел не пустой.
- Гигиена: доля кириллицы среди букв ≥ 0,6 (английские аббревиатуры DSCR, EBITDA, LME допустимы); нет кодов `ErrorCode` как отдельных слов; нет `Traceback` и `File "…", line`; нет `\b(IN|OUT)\d+\b`; нет имён инструментов каталога и `write_todos` / `read_file`.

### D5. Eval на GigaChat (`scripts/eval/answer_structure.py`)

- 6 запросов по Methanex: сценарный (EBITDA при цене метанола), относительный диапазон («±20 %»), подбор цели, сравнение двух лет, запрос без года (ожидается вопрос — проверяется только гигиена), вопрос на английском.
- Прогон в Docker-образе приложения (LibreOffice, GigaChat по `.env`), Langfuse выключен на время прогона: агент собирается `AgentFactory` с реальной моделью и каталогом, книга загружается в реестр как при `/upload`.
- Для каждого ответа: `is_analytic`, `structure_issues`, `hygiene_issues`, число вызовов модели и инструментов, время. JSON в `scripts/eval/results/answer_structure_<дата>.json`, сводка — в раздел «Результаты» этого design.
- Порог для приёмки story: ни одного нарушения гигиены; структура соблюдена в ≥ 4 из 5 аналитических ответов. Ниже порога — правка skill и повтор (не больше двух итераций), иначе — отчёт и решение разработчика.

## Risks / Trade-offs

- [Сообщение закрепления после вопроса пользователя: модель может отвечать на текст skill] → тег `<skill …>` и вступительная фраза skill «это правила оформления ответа, а не вопрос»; проверяется eval D5.
- [Текст skill занимает контекст каждой сессии] → ≤ 300 строк, один раз на сессию; размер слоёв — S2.7.
- [Проверка структуры по заголовкам хрупка к стилю модели] → допускаются `#`–`###` и `**…**`, регистр и двоеточие; формат заголовков задан в skill.

Только v2. Откат — убрать skill из каталога и из `DEFAULT_PINNED` (до S3.5 — в коде).

Правки по итерациям:
1. Skill: запрет ID, названий инструментов, кодов и статусов вынесен в начало («Главное правило») и повторён в «Где в модели»; пример ответа с готовыми фразами заменён шаблоном с заглушками — модель дословно копировала из примера оценки («риск для обслуживания долга умеренный»), не следующие из её цифр. Eval: ответ-вопрос при шаге `blocked` не проверяется на структуру и считается отдельно (`asked_instead_of_answer`) — по FR-12 вопрос даётся без разделов.
2. Skill: образец вопроса о выборе показателя названиями («Метанол» или «Этилен, CFR Китай»?) и антипример с ID — запрет без образца модель нарушала.

Наблюдения вне S3.2 (для S3.3, S4.1, S5.1):
- **FR-10:** запрос без года (Q5) во всех трёх прогонах посчитан с выдуманным годом (2026, 2026, 2024) вместо вопроса о годе. Предпроверка `missing_input` срабатывает, только если модель не передала год; модель его подставляет сама. Нужны правило в skills сценариев (S3.3) и метрика в eval (S5.1).
- **Лишние вопросы:** Q3 («цена метанола для EBITDA 1000 в 2026») в итерациях 1–2 закончился вопросом о годе и цели, которые в запросе есть: `find_input_for_target` вернул `missing_input` — модель не передала аргументы. В исходном прогоне Q2 и Q4 спрашивали выбор между «Метанол» и «Этилен» при однозначном термине. Это FR-6 / FR-10 — skill `target-seeking` (S3.3) и eval S5.1.
- **FR-13:** в ответах встречаются производные числа, посчитанные моделью («рост цены на 66 %», «+360 млн на каждые 100»). Ожидаемо до `derive` (S1.7) и `AnswerGroundingGuard` (S4.1).
- Модель иногда читает `economic-answer` через `read_file`, хотя он закреплён (Q1, Q4–Q6): лишний вызов, на ответ не влияет; метрика для S5.1.
